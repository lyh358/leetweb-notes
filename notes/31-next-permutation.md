# 力扣 31. 下一个排列 — 学习笔记

## 一、题目概述

实现获取 **下一个排列** 的函数，算法需要将给定数字序列重新排列成字典序中下一个更大的排列。

> 如果不存在下一个更大的排列，则将数字重新排列成最小的排列（即升序排列）。
>
> 必须**原地**修改，只允许使用额外常数空间。

---

## 二、核心思路（三步走）

想象你在用这些数字组成一个"密码锁"，要找到**刚好比当前大一点的下一个组合**。

### 直觉解释

假设当前排列是：`[1, 2, 7, 4, 3, 1]`

要从右边找突破口——因为右边变动对整体数值影响最小：

1. **找「较小数」**：从右往左看，`7→4→3→1` 一直降序，直到 `2 < 7`，发现 `2` 是「较小数」（索引 `i=1`）
   - 为什么从右边找？因为越靠右，交换后整体增幅越小

2. **找「较大数」**：在 `2` 的右边 `[7,4,3,1]` 中，找**刚好比 2 大的最小数**，从右往左第一个满足的是 `3`（索引 `j=4`）
   - 为什么是 `3` 而不是 `4` 或 `7`？因为要让增幅尽可能小

3. **交换 + 反转**：交换 `2` 和 `3` 得到 `[1, 3, 7, 4, 2, 1]`，然后把 `3` 右边的 `[7,4,2,1]` 反转成升序 `[1, 2, 4, 7]`
   - 为什么反转？因为交换后右边一定是降序，反转即升序，保证增幅最小

最终结果：`[1, 3, 1, 2, 4, 7]` ✅

## 三、代码实现

```cpp
class Solution {
public:
    void nextPermutation(vector<int>& nums) {
        int n = nums.size();
        if (n <= 1) return;

        // ========== 第一步：从右向左找「较小数」 ==========
        // 目标：找到第一个满足 nums[i] < nums[i+1] 的位置 i
        // 含义：nums[i] 是「较小数」，它右边的子数组是降序的
        // 为什么从右找？因为越靠右，交换后对整体数值的影响越小
        int i = n - 2;
        while (i >= 0 && nums[i] >= nums[i + 1]) {
            i--;
        }

        // ========== 第二步：如果找到了「较小数」 ==========
        // 如果 i >= 0，说明存在下一个更大的排列
        // 需要在 i 的右边找「较大数」
        if (i >= 0) {
            // 从右向左找第一个满足 nums[j] > nums[i] 的位置 j
            // 为什么从右找？因为右边是降序的，从右找第一个大于 nums[i] 的数
            // 就是「刚好比 nums[i] 大的最小数」，保证增幅最小
            int j = n - 1;
            while (j > i && nums[j] <= nums[i]) {
                j--;
            }

            // 交换「较小数」和「较大数」
            // 交换后，i 右边的子数组仍然是降序的
            swap(nums[i], nums[j]);
        }
        // 如果 i < 0，说明整个数组是降序的（如 [3,2,1]）
        // 不存在下一个更大的排列，直接跳到第三步：反转整个数组得到最小排列

        // ========== 第三步：反转 i 右边的子数组 ==========
        // 交换后，nums[i+1 ... n-1] 一定是降序的
        // 将其反转为升序，得到「刚好大一点」的排列
        // 如果是 i < 0 的情况（整个数组降序），这里就是反转整个数组
        reverse(nums.begin() + i + 1, nums.end());
    }
};
```

## 四、复杂度分析

| 指标 | 复杂度 | 说明 |
|------|--------|------|
| **时间复杂度** | $O(n)$ | 最坏情况下三次线性扫描（找 i、找 j、反转），但都是单向的，合起来仍是 $O(n)$ |
| **空间复杂度** | $O(1)$ | 原地操作，仅使用常数额外变量 |

## 五、流程图解（示例）

数组：`[1, 2, 7, 4, 3, 1]`

```
初始: [1, 2, 7, 4, 3, 1]
          ↑
          i=1 (2 是「较小数」，因为 2 < 7)

在右边找「较大数」: 从右往左，1→3→4→7，第一个 > 2 的是 3
                  ↑
                  j=4

交换后: [1, 3, 7, 4, 2, 1]
             ↑        ↑
             i        j

反转 i 右边: [1, 3, 1, 2, 4, 7]
                ↑  ↑  ↑  ↑
                反转为升序

结果: [1, 3, 1, 2, 4, 7] ✅
```

## 六、边界情况

| 输入 | 说明 | 输出 |
|------|------|------|
| `[1, 2, 3]` | 升序，存在下一个 | `[1, 3, 2]` |
| `[3, 2, 1]` | 降序，不存在下一个 | `[1, 2, 3]`（循环到最小） |
| `[1, 1, 5]` | 有重复元素 | `[1, 5, 1]` |
| `[1]` | 单元素 | `[1]` |

## 七、踩坑记录

### 错误代码

```cpp
class Solution {
public:
    void nextPermutation(vector<int>& nums) {
        int n = nums.size();
        if(n <= 1) return;
        int i = n - 2;
        while(i >= 0 && nums[i] >= nums[i + 1]) {
            i--;
        }
        int j = n - 1;
        while(j > i && nums[j] <= nums[i]) {
            j--;
        }
        swap(nums[i], nums[j]);              // ❌ 缺少 i >= 0 的判断
        reverse(nums.begin() + i + 1, nums.end());
    }
};
```

### 问题分析

当输入是**降序数组**（如 `[3, 2, 1]`）时，`i` 会一直减到 `-1`：

| 步骤 | 输入 `[3, 2, 1]` | 结果 |
|------|------------------|------|
| 找 `i` | `i` 从 1 → 0 → -1 | `i = -1`（整个数组降序） |
| 找 `j` | `j = 2` | 正常 |
| `swap` | `swap(nums[-1], nums[2])` | **越界访问！** |
| `reverse` | `reverse(nums.begin(), nums.end())` | 这步其实是对的 |

### 错误原因

> **当 `i < 0` 时，说明整个数组是降序的，不存在「较小数」，此时不需要交换，直接反转整个数组即可。**
>
> 但原代码没有判断 `i >= 0`，导致 `swap(nums[-1], ...)` 越界。

### 修正方法

在交换前加上 `if (i >= 0)` 的判断：

```cpp
if (i >= 0) {
    int j = n - 1;
    while (j > i && nums[j] <= nums[i]) {
        j--;
    }
    swap(nums[i], nums[j]);
}
// 如果 i < 0，跳过交换，直接到 reverse
```

> 当 `i < 0` 时，`reverse(nums.begin() + i + 1, nums.end())` 变成 `reverse(nums.begin(), nums.end())`，正好把降序数组反转为升序，得到最小排列。

### 教训

- **边界条件永远是坑**：降序数组是"不存在下一个更大排列"的情况，容易漏掉
- **从右往左扫描时，一定要考虑扫到头（`i = -1`）的情况**
- **交换操作前，务必确认索引有效**

---

## 八、关键收获


1. **「下一个排列」的本质是找"刚好大一点"**。不是找最大，而是找字典序的下一个邻居。
2. **从右往左找突破口**，因为右边的变动对整体数值影响最小，符合"刚好大一点"的要求。
3. **交换后必须反转右边子数组**。因为右边原本是降序，反转后变成升序，这才是"最小增幅"。
4. **三步法可以统一处理所有情况**：
   - 正常情况（找到 i）：交换 + 反转后半部分
   - 降序情况（i = -1）：直接反转整个数组
   - 代码上统一为：找 i → 若 i≥0 则找 j 并交换 → 反转 `i+1` 到末尾
