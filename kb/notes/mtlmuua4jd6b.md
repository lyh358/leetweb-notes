# 一、C/C++ 语言

## 1. `const`

### 面试简答

`const` 表示对象不能通过当前接口被修改，主要用于表达只读语义、限制误操作并帮助接口设计。它可以修饰变量、指针、函数参数、返回值和 C++ 成员函数。

```cpp
const int a = 10;             // a 不可修改
const char* p1 = buf;         // 不能通过 p1 修改所指内容
char* const p2 = buf;         // p2 本身不能指向别处
const char* const p3 = buf;   // 指针和所指内容都不能通过 p3 修改

class A {
public:
    int size() const;         // 不修改对象的逻辑状态
};
```

### 顶层 `const` 和底层 `const`

- **顶层 const**：对象本身不可修改，如 `char* const p`。
- **底层 const**：指针或引用所指对象不可通过该接口修改，如 `const char* p`。

按值传参会复制对象，因此顶层 const 通常不影响函数签名；底层 const 会影响类型兼容性。

### `const` 大数组占内存吗

占存储空间，但占 Flash、ROM 还是 RAM 不能一概而论。

- 文件作用域 `const` 数组通常进入只读段 `.rodata`；在 MCU 上常被链接到 Flash。
- 有些平台启动时会把只读数据映射或复制到 RAM。
- 函数内自动 `const` 数组可能位于栈上，也可能被编译器优化。
- 是否真正分配空间还受优化、取地址、链接脚本影响。

因此不要绝对回答“只占 Flash、不占 RAM”，应说：**通常进入只读段，在典型 MCU 链接配置下主要占 Flash，最终以内存映射和链接脚本为准。**

### 能否强转去掉 `const`

```cpp
const int x = 1;
int* p = const_cast<int*>(&x);
*p = 2;                       // 未定义行为
```

`const_cast` 可以去掉类型系统中的 const，但如果原对象本身就是 const，写入属于未定义行为，可能写只读存储并触发异常。如果原对象本来可写，只是经 `const` 接口传递，去掉 const 后修改才可能合法。

### 返回值加 `const`

- 返回 `const T&` 可防止调用者通过该引用修改对象，但必须保证引用生命周期。
- 对现代 C++ 的普通按值返回 `const T` 通常没有价值，还可能妨碍移动语义。

## 2. `volatile`

### 面试简答

`volatile` 告诉编译器：该对象可能被当前代码之外的因素改变，每次访问都应按语言和编译器规则真实读取或写入，不能把值长期缓存到寄存器。常见场景是**内存映射寄存器、部分中断共享标志和极底层硬件代码**。

```cpp
volatile uint32_t* const UART_STATUS =
    reinterpret_cast<volatile uint32_t*>(0x40001000);
```

### `volatile const`

```cpp
volatile const uint32_t* status;
```

表示软件不能通过该指针写入，但硬件可能异步改变其值，适合只读状态寄存器。

### `volatile` 保证线程安全吗

不保证。它通常不提供：

- 原子性；
- 线程间 happens-before 关系；
- 内存顺序；
- 复合操作互斥。

```cpp
volatile int count = 0;
count++;  // 读、加、写三步，多线程仍会丢失更新
```

线程同步应使用 `std::atomic`、锁或操作系统同步原语。ISR 与任务共享数据时，还要结合平台的原子访问能力、临界区和内存屏障；仅加 `volatile` 往往不够。

### `volatile` 与原子操作区别

- `volatile` 主要约束编译器对访问的优化。
- 原子操作保证某次读改写不可被观察为中间状态，并可提供规定的内存序。
- 硬件寄存器通常需要 `volatile`，线程共享变量通常需要原子或锁。

## 3. `static`

### 三种常见含义

1. **函数内 static**：静态存储期，只初始化一次，程序结束时销毁。
2. **文件作用域 static**：内部链接，只在当前翻译单元可见。
3. **类 static 成员**：属于类本身，由所有对象共享；静态成员函数没有 `this` 指针。

### 局部 static 放在哪里

不在普通调用栈中。已初始化且非零的通常在 `.data`，零初始化或未显式初始化的通常在 `.bss`；只读常量和具体布局由实现决定。

### 多线程初始化和访问

C++11 起，函数局部 static 的**初始化过程**由语言保证线程安全；但初始化完成后的读写不自动线程安全。

```cpp
static int count = 0;
++count;  // 多线程数据竞争
```

可根据场景使用互斥锁、`std::atomic` 或线程局部存储 `thread_local`。

## 4. 结构体、联合体与字节对齐

### 结构体和联合体

- `struct` 的成员拥有各自存储，通常按声明顺序排列并插入 padding。
- `union` 的成员共享同一段存储，同一时刻通常只应读取当前有效成员；大小至少能容纳最大成员，并满足最严格对齐要求。

### 结构体大小计算

一般规则：

1. 每个成员起始地址满足自身对齐要求；
2. 成员之间可能插入 padding；
3. 结构体整体大小是其整体对齐值的整数倍；
4. `#pragma pack`、`alignas`、ABI 会改变结果。

```cpp
struct S {
    char  a;   // offset 0
    int   b;   // 通常 offset 4
    short c;   // 通常 offset 8
};             // 常见大小 12，而不是 7
```

### 强制对齐与紧凑布局

```cpp
struct alignas(16) Aligned { char data[16]; };

#pragma pack(push, 1)
struct Packet { uint8_t type; uint32_t len; };
#pragma pack(pop)
```

网络包、Flash 布局和硬件协议不能直接依赖本机结构体布局，最好显式序列化并处理大小端。

### 未对齐访问为什么可能 HardFault

部分 MCU 或特定指令不支持未对齐访问。访问一个不满足对齐要求的地址时，可能触发 UsageFault/BusFault，最终升级为 HardFault；即使硬件支持，访问也可能更慢。排查时查看 CFSR、HFSR、BFAR/MMFAR、异常栈中的 PC/LR，并检查强转指针和 packed 结构体访问。

## 5. `extern "C"`

### 面试简答

C++ 支持函数重载，会进行 name mangling；C 通常使用简单符号名。`extern "C"` 告诉 C++ 编译器按 C 语言链接规则导出或查找符号，使 C++ 能与 C 库链接。

```cpp
#ifdef __cplusplus
extern "C" {
#endif

void driver_init(void);

#ifdef __cplusplus
}
#endif
```

头文件使用上述保护后，可以同时被 C 和 C++ 源文件包含。

### C 调用 C++

为 C++ 实现提供 `extern "C"` 包装函数，对外只暴露 C ABI；类、重载、异常和模板不能直接作为 C 接口。异常不能跨 C ABI 边界传播，应在包装层捕获并转换为错误码。

## 6. `new`、`malloc`、`kmalloc`、`vmalloc`

### `new` 与 `malloc`

| 对比 | `new/delete` | `malloc/free` |
|---|---|---|
| 语言 | C++ 运算符 | C 库函数 |
| 返回类型 | 目标类型指针 | `void*` |
| 构造/析构 | 会调用 | 不会调用 |
| 失败行为 | 默认抛 `std::bad_alloc` | 返回 `nullptr` |
| 数组 | `new[]/delete[]` | 只分配字节 |
| 扩容 | 无直接 `realloc` | 支持 `realloc` |

```cpp
auto p = new (std::nothrow) Foo;  // 失败返回 nullptr
```

### 定位 new（placement new）

在调用者提供的内存上构造对象，不负责分配内存：

```cpp
alignas(Foo) unsigned char storage[sizeof(Foo)];
Foo* p = new (storage) Foo();
p->~Foo();
```

适合对象池、共享内存和确定性内存管理，必须保证容量、对齐和显式析构。

### Linux 内核中的 `kmalloc` 与 `vmalloc`

- `kmalloc`：虚拟地址连续，通常物理地址也连续，适合较小对象和需要物理连续/DMA 约束的场景。
- `vmalloc`：虚拟地址连续，物理页可不连续，适合较大且不要求物理连续的内核缓冲区，映射开销更高。
- 用户态 `malloc`：向进程堆分配虚拟地址，底层可能使用 `brk` 或 `mmap`，物理页通常按需建立。

DMA 是否可直接使用还需看设备、IOMMU、DMA API 和缓存一致性，不能简单等同于“kmalloc 一定可 DMA”。

## 7. C++ 智能指针

### 面试简答

- `unique_ptr`：独占所有权，不可复制、可移动，默认首选。
- `shared_ptr`：引用计数共享所有权，最后一个拥有者释放对象。
- `weak_ptr`：不增加强引用计数，用于观察 `shared_ptr` 管理的对象并打破循环引用。

### 循环引用

```cpp
struct B;
struct A { std::shared_ptr<B> b; };
struct B { std::shared_ptr<A> a; }; // 两者互相保持，无法释放
```

将非拥有关系的一侧改为 `weak_ptr`，使用前调用 `lock()` 获得临时 `shared_ptr`。

### 智能指针线程安全吗

不同 `shared_ptr` 实例共享的控制块，其引用计数增减通常是线程安全的；但：

- 被管理对象本身不自动线程安全；
- 同一个 `shared_ptr` 对象被多个线程同时非 const 修改会数据竞争；
- 需要时使用锁或 `std::atomic<std::shared_ptr<T>>`（C++20）。

### `make_shared` 优势

通常把对象和控制块一次分配，减少分配次数、改善局部性，并避免某些表达式中的资源泄漏风险。代价是对象内存通常要等弱引用控制块一起释放，且不适用于自定义删除器或必须分离分配的场景。

## 8. 虚函数、纯虚函数与抽象类

### 面试简答

虚函数提供运行时多态；纯虚函数用于定义必须由派生类实现的接口。含有未实现纯虚函数的类是抽象类，不能直接实例化。

```cpp
struct Device {
    virtual int read() = 0;
    virtual ~Device() = default;
};
```

### 虚表和虚指针

常见实现中，每个多态对象包含虚表指针 `vptr`，指向类的虚函数表 `vtable`。调用虚函数时通过虚表间接找到最终覆盖函数。这是主流 ABI 的实现方式，但 C++ 标准没有规定必须使用虚表。

- 虚表通常位于程序映像的只读数据区域。
- `vptr` 位于每个多态对象内部。
- 虚调用增加一次间接寻址，并可能影响内联和分支预测。

### 构造函数为什么不能是虚函数

创建对象前必须先确定对象的具体类型和大小，构造过程中虚机制也尚未完整建立，因此构造函数不能是虚函数。可用工厂函数实现“多态创建”。

### 为什么基类析构函数通常应为虚函数

如果通过基类指针删除派生对象，而基类析构非虚，会产生未定义行为，派生部分可能无法正确析构。

```cpp
Base* p = new Derived;
delete p;  // Base 析构应为 virtual
```

如果一个类明确不允许通过基类指针删除，也可以使用受保护的非虚析构函数表达约束。

## 9. `map` 与 `unordered_map`

| 特性 | `map` | `unordered_map` |
|---|---|---|
| 常见实现 | 红黑树 | 哈希表 |
| 顺序 | 按 key 有序 | 无序 |
| 查找/插入/删除 | `O(log n)` | 平均 `O(1)`，最坏 `O(n)` |
| 范围查询 | 支持 | 不擅长 |
| 迭代器失效 | 删除对应元素时失效 | rehash 可能使迭代器失效 |

哈希冲突常用拉链法或开放寻址解决；C++ 标准只规定行为和复杂度，不强制具体冲突实现。需要有序遍历、上下界和稳定最坏复杂度时选 `map`；只做精确查找且哈希质量好时选 `unordered_map`。嵌入式还要评估动态内存、节点开销和确定性。

# 二、Linux 与 RTOS

## 1. 进程与线程

### 面试简答

进程是资源隔离和保护的基本单位，拥有独立虚拟地址空间、页表和资源表；线程是 CPU 调度的基本执行流。同一进程的线程共享代码、堆、全局变量和文件描述符，但拥有独立栈、寄存器状态和线程局部数据。

### 常见 IPC

| 方式 | 特点与场景 |
|---|---|
| 管道/命名管道 | 字节流，适合亲缘进程或简单本机通信 |
| 消息队列 | 保留消息边界，异步解耦 |
| 共享内存 | 拷贝少、吞吐高，但必须自行同步 |
| 信号 | 传递异步事件，信息量有限 |
| Socket | 本机或网络通用，接口统一 |
| 信号量 | 主要用于同步和计数，不承载业务数据 |
| 内存映射文件 | 文件与内存共享、进程间共享 |

### 共享内存需要注意什么

共享内存只解决“双方都能看见数据”，不解决并发正确性。还需处理：

- 互斥、读写锁、信号量或原子变量；
- 内存可见性和内存序；
- 数据生命周期、版本和长度；
- 崩溃恢复与健壮互斥锁；
- 指针不能直接跨不同进程地址空间传递，通常存偏移量。

### 线程通信和进程通信区别

线程天然共享地址空间，可直接共享对象但更容易数据竞争；进程默认隔离，需要内核 IPC 或显式共享内存，隔离性更好但通常管理成本更高。

### 僵尸进程和孤儿进程

- **僵尸进程**：子进程已经退出，但父进程未调用 `wait/waitpid` 回收退出状态。处理方式是父进程正确回收，或设置适当的 `SIGCHLD` 处理。
- **孤儿进程**：父进程先退出，仍运行的子进程会被 init/systemd 或 subreaper 接管，不等于资源泄漏。

### 上下文切换做什么

保存和恢复寄存器、栈指针、程序计数器、调度状态等；进程切换还可能切换地址空间和页表，影响 TLB 与缓存，因此通常比同进程线程切换更重。实际开销取决于是否跨 CPU、内核策略和工作集。

## 2. 锁体系

### 互斥锁、自旋锁、读写锁

- **互斥锁**：竞争失败的线程睡眠，适合临界区较长或可能阻塞的场景。
- **自旋锁**：竞争失败持续占用 CPU 等待，适合不可睡眠上下文和极短临界区；单核环境常需要配合禁止抢占/中断才有意义。
- **读写锁**：允许多个读者并发、写者独占，适合读多写少；可能有公平性和写者饥饿问题。

### 互斥锁和自旋锁怎么选

先看上下文能否睡眠，再看临界区长度：

- ISR/原子上下文不能睡眠，只能使用适用的自旋锁、关中断或无锁机制。
- 线程上下文且临界区较长、可能阻塞，使用互斥锁。
- 临界区极短且睡眠/唤醒成本更大时，可考虑自旋锁。

不要在持有自旋锁时执行可能睡眠、耗时或调用不确定的操作。

### 优先级反转与优先级继承

低优先级任务持有锁，高优先级任务等待该锁，中优先级任务不断抢占低优先级任务，导致高优先级任务长时间无法运行，这就是优先级反转。

优先级继承会临时把锁持有者提升到最高等待者的优先级，使其尽快释放锁；释放后恢复原优先级。优先级天花板是另一种预防策略。

FreeRTOS 中通常是**互斥量**支持优先级继承，普通二值信号量通常不支持。其他系统是否支持取决于具体同步对象和协议，不能推广成语言层面的绝对结论。

### ISR 中能否使用互斥锁或自旋锁

- 不能使用会睡眠的普通互斥锁。
- Linux 内核 ISR 可使用对应的自旋锁变体，并正确处理中断状态，但临界区必须极短。
- RTOS ISR 应使用专门的 `FromISR` API、短临界区或无锁队列；不要笼统地说“中断里可直接用普通信号量”。ISR 通常只发送/释放信号量，不能阻塞等待。

### 死锁四个必要条件

1. 互斥；
2. 占有并等待；
3. 不可抢占；
4. 循环等待。

### 工程排查

1. 复现并记录卡死时刻、任务状态和锁等待关系；
2. Linux 使用 `gdb`、`pstack`、`perf`、ftrace、lockdep；RTOS 查看任务列表、事件列表和各任务栈；
3. 获取所有线程/任务调用栈，建立“谁持有什么、等待什么”的依赖图；
4. 检查锁顺序、遗漏解锁、递归加锁和持锁阻塞；
5. 统一锁顺序，缩小临界区，使用 RAII，必要时超时和 try-lock；
6. 增加压力测试与锁等待监控验证修复。

## 3. 原子操作

### 面试简答

原子操作在其他执行单元看来不可被拆分，常由 CPU 原子指令、独占访问指令或短暂关中断实现。C++ 使用 `std::atomic<T>`，Linux 内核和 RTOS 有各自原子 API。

### 能否替代锁

适合计数器、状态位、引用计数、单生产者单消费者索引等简单共享状态。多个变量需要保持整体不变量、临界区包含复杂逻辑或阻塞操作时，锁更合适。无锁算法还必须正确处理内存序、ABA 和对象生命周期。

### `volatile` 能否实现原子性

不能。`volatile` 约束访问优化，原子性和跨核可见性需要原子指令及正确内存序。

## 4. 虚拟内存与 MMU

### 面试简答

MMU 根据页表把虚拟地址转换为物理地址，并提供权限检查、地址空间隔离、共享映射和按需分页。虚拟地址按页划分，物理内存按页框管理；TLB缓存近期转换结果。

### 缺页异常流程

1. CPU访问虚拟地址，页表项无有效映射或权限不符；
2. 进入内核缺页异常处理；
3. 判断地址是否合法；
4. 合法时分配页框、从文件/交换区载入或建立写时复制映射；
5. 更新页表和TLB后重试指令；
6. 非法访问则向进程发送 `SIGSEGV` 等异常。

### 无 MMU 的 MCU 如何管理内存

CPU通常直接使用物理地址，没有进程级地址隔离和按需分页。RTOS可使用固定分区、内存池、伙伴/堆算法、静态任务栈和 MPU提供有限区域保护。实时系统通常优先静态分配或固定块内存池，以提高确定性并减少碎片。

---

## 5. Linux 与 RTOS 对比

| 维度 | Linux | RTOS |
|---|---|---|
| 目标 | 通用功能、吞吐和生态 | 确定性、低延迟、资源受限 |
| 地址空间 | 通常有 MMU 和进程隔离 | 常为单地址空间，可选 MPU |
| 调度 | 多策略、复杂公平性 | 固定优先级抢占常见 |
| 内存 | 虚拟内存、按需分页 | 静态、堆或内存池，无分页常见 |
| 生态 | 网络、文件系统、驱动丰富 | 小巧、启动快、硬实时更易控制 |

复杂 UI、多进程隔离、完整网络/文件系统和丰富驱动通常选 Linux；控制环、严格截止期、低功耗快速启动和资源紧张通常选 RTOS。很多产品是 Linux+MCU/RTOS 异构组合。

### FreeRTOS 任务切换与 PendSV

以 Cortex-M 为例：SysTick 或事件使更高优先级任务就绪，调度器请求 PendSV；PendSV 以低异常优先级运行，保存当前任务寄存器到其栈，更新任务控制块中的栈指针，选择下一任务，恢复其上下文并异常返回。PendSV不是“任务异常退出后才触发”，而是专门用于把上下文切换延后到合适时机。

---

## 6. 内存分配与程序布局

### 程序内存布局

- `.text`：机器代码，通常只读可执行；
- `.rodata`：只读常量；
- `.data`：已初始化的可写全局/静态变量；
- `.bss`：零初始化或未显式初始化的全局/静态变量；
- heap：动态分配区，通常向高地址增长；
- stack：调用帧、局部变量和保存的上下文，通常向低地址增长，但方向由平台决定。

### 用户态 `malloc` 大致流程

分配器先在用户态管理的 arena/free list 中寻找可用块；没有合适块时通过 `brk` 或 `mmap` 向内核扩展虚拟地址空间。物理页常在首次访问时通过缺页异常按需分配。`free` 通常先归还给分配器，不一定立即归还内核。

### 堆碎片及缓解

- 外部碎片：空闲总量足够但不连续；
- 内部碎片：分配块大于实际需求。

嵌入式缓解方法：启动期集中分配、运行期避免频繁不定长分配、固定块内存池、对象池、区域分配器、限制尺寸类别、监控高水位和最长分配耗时。

### 栈溢出检测

- 编译器 stack protector/canary；
- RTOS栈填充并检查高水位；
- MPU guard region；
- 静态栈深分析和压力测试；
- Cortex-M故障寄存器与异常栈回溯。

### 内存泄漏与越界排查

- Linux：ASan、LSan、Valgrind、gdb、heap profiler；
- 内核：KASAN、kmemleak、slab调试；
- MCU/RTOS：分配封装、调用点记录、内存水位、guard pattern、MPU、HardFault寄存器和 map 文件。

---

## 7. CPU 调度

调度器在多个可运行任务之间决定谁获得 CPU，以满足响应时间、吞吐、公平性或截止期要求。

### RTOS 抢占式调度

更高优先级任务进入 Ready 后可以抢占当前低优先级任务。同优先级任务是否时间片轮转取决于配置；任务阻塞、延时、主动让出或时间片耗尽都可能触发调度。

### 时间片轮转

多个同优先级就绪任务轮流运行固定时间片，提高公平性，但会增加上下文切换。严格实时任务通常依赖优先级和阻塞事件，而不是只依赖轮转。

---

## 8. 中断

### 基本处理流程

外设产生中断，控制器仲裁，CPU保存最小现场并跳转到 ISR；ISR确认来源、处理必要状态、清除中断标志，必要时唤醒下半部或任务，随后恢复现场。

### 上半部和下半部

- 上半部/硬中断：快速完成必须立即处理的操作。
- 下半部：把耗时、可延后的工作交给 softirq、tasklet、workqueue、线程化中断或 RTOS任务。

### ISR 中可以做什么

适合：读取/确认状态、清中断、搬少量数据、记录时间戳、向队列投递事件、唤醒任务。

避免：阻塞等待、普通互斥锁、动态内存分配、长循环、日志刷屏、复杂协议和不可重入函数。

### ISR 中调用 `malloc` 会怎样

常规 `malloc` 可能持锁、耗时不确定且不可重入，ISR中调用可能死锁、破坏堆或导致不可接受的中断延迟。应预分配、使用专用固定块池，或把分配推迟到任务上下文。Linux内核也不是使用用户态 `malloc`；原子上下文只能使用允许的 GFP 标志和对应内核API，并仍应谨慎。

---

## 9. TCP 与 UDP

### 基础区别

| TCP | UDP |
|---|---|
| 面向连接、可靠、有序字节流 | 无连接、尽力而为、保留报文边界 |
| 拥塞控制、流量控制、重传 | 协议本身不提供这些能力 |
| 头部和状态较复杂 | 头部小、延迟低、便于广播/组播 |

### 三次握手

客户端 `SYN`，服务端 `SYN+ACK`，客户端 `ACK`。它同步双方初始序列号并确认双向收发能力，同时建立连接状态。

### 四次挥手

TCP是全双工，双方发送方向要分别关闭；一方 `FIN` 后对方先 `ACK`，待剩余数据发送完再发送自己的 `FIN`，最后收到 `ACK`。某些情况下 ACK 与 FIN 可合并，因此抓包不一定永远是严格四个独立报文。

### 滑动窗口

发送方可在未收到逐包确认前连续发送窗口内数据。接收窗口用于流量控制，拥塞窗口用于保护网络；实际可发送量受两者较小值限制。

### UDP 如何实现可靠传输

应用层增加序列号、ACK、超时重传、去重、乱序重排、校验、流控和拥塞控制。QUIC就是在UDP之上实现可靠安全传输的典型协议。是否值得自研取决于业务需求。

### 如何选择

文件、配置、控制命令且要求可靠有序时优先TCP；实时音视频、遥测、发现广播和允许少量丢包的低延迟业务可选UDP。不能只根据“快慢”选择，要看消息边界、丢包容忍、延迟和网络环境。

---

# 三、SPI、I²C 与存储

## 1. SPI

### 基础

常见四线：

- `SCLK`：主机时钟；
- `MOSI`：主机到从机；
- `MISO`：从机到主机；
- `CS/SS`：片选，通常低有效。

SPI全双工、没有统一设备地址，主机通常使用独立CS选择从机；多个设备可共享SCLK/MOSI/MISO，但每个设备通常需要独立CS，并确保未选中的从机释放MISO。

### 多设备同时读取怎么做

同一SPI控制器和总线不能真正同时传输多个设备，只能通过总线锁和片选串行调度。若要求真正并行，需要多个SPI控制器、不同总线或外部硬件支持。

### GPIO不够怎么办

- GPIO扩展器、译码器或移位寄存器扩展CS；
- 级联支持菊花链的器件；
- 使用外设控制器的硬件CS；
- 用普通GPIO实现**软件控制片选**。

“软件片选”只是由驱动手动拉高/拉低GPIO，不会凭空减少每个设备所需的片选数量；GPIO不足时仍需要扩展器或译码电路。

### SPI失败分层排查

1. **供电与连接**：电压、地、线序、CS、焊接、上拉/下拉；
2. **时序**：示波器/逻辑分析仪检查CPOL、CPHA、频率、CS建立保持时间；
3. **配置**：位宽、大小端、全双工/半双工、最高频率；
4. **驱动**：DMA长度、缓存一致性、超时、中断和并发锁；
5. **协议**：命令、地址、dummy cycle、状态寄存器和设备启动时间；
6. 降低频率、单设备、轮询模式、发送已知模式逐层缩小范围。

---

## 2. I²C

I²C通常两根开漏线：`SCL`和`SDA`，需要上拉电阻。主机通过7位或10位地址选择从机，同一总线可以挂多个地址不同的设备，并支持ACK/NACK和仲裁。

### 地址冲突怎么办

- 使用器件地址配置引脚；
- I²C多路复用器；
- 分配到不同控制器/总线；
- 对支持的器件在启动阶段重新编址。

### NACK或通信异常排查

1. 检查地址是否包含读写位、7位/8位表示是否混淆；
2. 检查电源、共地、上拉阻值和电平兼容；
3. 用逻辑分析仪看START、地址、ACK、STOP和时钟拉伸；
4. 降低速率，检查总线电容和上升沿；
5. 检查寄存器地址宽度、重复起始和读写顺序；
6. SDA被拉低时尝试总线恢复：按器件规范输出若干SCL并产生STOP；
7. 排除多主仲裁、中断/DMA状态机和并发访问问题。

---

## 3. NOR Flash、EEPROM 与 SSD

### NOR Flash 与 EEPROM

- NOR Flash容量通常更大，按页编程、按扇区/块擦除，支持随机读取和部分器件XIP；写前通常要擦除。
- EEPROM通常支持更细粒度字节/页写，擦写耐久度常更高，容量较小，适合配置参数。

实际耐久度、页大小和写入限制必须看具体器件手册。

### 磨损均衡

避免总在同一物理块写入，把擦写均匀分布到不同块。分静态和动态磨损均衡，通常由SSD控制器FTL完成。

### 垃圾回收

Flash不能原地覆盖，更新后旧页变无效。垃圾回收选择有效数据少的块，把有效页迁移后擦除整块，生成新的空闲块。它会引入写放大和尾延迟，因此需要预留空间、后台回收和合理策略。

# 五、ACM 手撕算法

> 默认 C++17。面试时先确认输入输出，再说思路、边界和复杂度，最后编码并用最小样例检查。

## 1. 链表倒数第 k 个节点

思路：快指针先走 `k` 步，再与慢指针一起走；快指针到末尾时，慢指针位于倒数第 `k` 个节点。`k<=0` 或不足 `k` 个节点返回空。

```cpp
#include <iostream>
using namespace std;

struct ListNode {
    int val;
    ListNode* next;
    explicit ListNode(int x) : val(x), next(nullptr) {}
};

ListNode* kthFromEnd(ListNode* head, int k) {
    if (k <= 0) return nullptr;
    ListNode* fast = head;
    for (int i = 0; i < k; ++i) {
        if (!fast) return nullptr;
        fast = fast->next;
    }
    ListNode* slow = head;
    while (fast) {
        fast = fast->next;
        slow = slow->next;
    }
    return slow;
}
```

时间 `O(n)`，额外空间 `O(1)`。

## 2. 合并两个有序数组

若第一个数组尾部容量足够，从后向前写，避免覆盖未处理元素。

```cpp
void mergeSorted(vector<int>& a, int m, const vector<int>& b, int n) {
    int i = m - 1, j = n - 1, k = m + n - 1;
    while (j >= 0) {
        if (i >= 0 && a[i] > b[j]) a[k--] = a[i--];
        else a[k--] = b[j--];
    }
}
```

时间 `O(m+n)`，额外空间 `O(1)`。

## 3. 合并两个有序链表

```cpp
ListNode* mergeLists(ListNode* a, ListNode* b) {
    ListNode dummy(0);
    ListNode* tail = &dummy;
    while (a && b) {
        if (a->val <= b->val) {
            tail->next = a;
            a = a->next;
        } else {
            tail->next = b;
            b = b->next;
        }
        tail = tail->next;
    }
    tail->next = a ? a : b;
    return dummy.next;
}
```

时间 `O(m+n)`，额外空间 `O(1)`。

## 4. 链表反转

```cpp
ListNode* reverseList(ListNode* head) {
    ListNode* prev = nullptr;
    while (head) {
        ListNode* next = head->next;
        head->next = prev;
        prev = head;
        head = next;
    }
    return prev;
}
```

时间 `O(n)`，额外空间 `O(1)`。关键是修改 `next` 前先保存后继。

## 5. 无重复字符最长子串

使用滑动窗口和字符最后出现位置。以下按字节处理；如果题目要求Unicode字符，需要先明确编码单位。

```cpp
#include <array>
#include <string>
#include <algorithm>
using namespace std;

int lengthOfLongestSubstring(const string& s) {
    array<int, 256> last;
    last.fill(-1);
    int left = 0, ans = 0;
    for (int right = 0; right < static_cast<int>(s.size()); ++right) {
        unsigned char ch = static_cast<unsigned char>(s[right]);
        left = max(left, last[ch] + 1);
        last[ch] = right;
        ans = max(ans, right - left + 1);
    }
    return ans;
}
```

时间 `O(n)`，空间 `O(1)`（固定字符集）。边界：空串、全相同、字符有符号性。

## 6. 字符串大数相加

```cpp
#include <algorithm>
#include <string>
using namespace std;

string addStrings(const string& a, const string& b) {
    int i = static_cast<int>(a.size()) - 1;
    int j = static_cast<int>(b.size()) - 1;
    int carry = 0;
    string ans;
    while (i >= 0 || j >= 0 || carry) {
        int x = i >= 0 ? a[i--] - '0' : 0;
        int y = j >= 0 ? b[j--] - '0' : 0;
        int sum = x + y + carry;
        ans.push_back(char('0' + sum % 10));
        carry = sum / 10;
    }
    reverse(ans.begin(), ans.end());
    return ans;
}
```

时间 `O(max(m,n))`，结果空间 `O(max(m,n))`。应确认输入是否允许空串、前导零和负数。

## 7. 接雨水

双指针维护左右最高柱。较低一侧的蓄水量已经可以确定。

```cpp
#include <vector>
#include <algorithm>
using namespace std;

long long trap(const vector<int>& h) {
    int left = 0, right = static_cast<int>(h.size()) - 1;
    int leftMax = 0, rightMax = 0;
    long long ans = 0;
    while (left < right) {
        if (h[left] <= h[right]) {
            leftMax = max(leftMax, h[left]);
            ans += leftMax - h[left];
            ++left;
        } else {
            rightMax = max(rightMax, h[right]);
            ans += rightMax - h[right];
            --right;
        }
    }
    return ans;
}
```

时间 `O(n)`，额外空间 `O(1)`。空数组时 `right=-1`，循环不会进入。

## 8. 下一个排列

步骤：从右找第一个下降位置 `i`；再从右找第一个大于它的元素交换；最后反转后缀。若整个序列降序，则反转成最小排列。

```cpp
#include <vector>
#include <algorithm>
using namespace std;

void nextPermutation(vector<int>& a) {
    int n = static_cast<int>(a.size());
    int i = n - 2;
    while (i >= 0 && a[i] >= a[i + 1]) --i;
    if (i >= 0) {
        int j = n - 1;
        while (a[j] <= a[i]) --j;
        swap(a[i], a[j]);
    }
    reverse(a.begin() + i + 1, a.end());
}
```

时间 `O(n)`，额外空间 `O(1)`。

## 9. 矩阵最长递增路径

把每个格子看作节点，只向更大值移动；严格递增保证没有环。DFS返回“从当前格开始的最长长度”，用记忆化避免重复计算。

```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
    int m = 0, n = 0;
    vector<vector<int>> memo;
    const int dx[4] = {1, -1, 0, 0};
    const int dy[4] = {0, 0, 1, -1};

    int dfs(const vector<vector<int>>& a, int x, int y) {
        if (memo[x][y]) return memo[x][y];
        int best = 1;
        for (int d = 0; d < 4; ++d) {
            int nx = x + dx[d], ny = y + dy[d];
            if (nx >= 0 && nx < m && ny >= 0 && ny < n &&
                a[nx][ny] > a[x][y]) {
                best = max(best, 1 + dfs(a, nx, ny));
            }
        }
        return memo[x][y] = best;
    }

public:
    int longestIncreasingPath(const vector<vector<int>>& a) {
        if (a.empty() || a[0].empty()) return 0;
        m = static_cast<int>(a.size());
        n = static_cast<int>(a[0].size());
        memo.assign(m, vector<int>(n));
        int ans = 0;
        for (int i = 0; i < m; ++i)
            for (int j = 0; j < n; ++j)
                ans = max(ans, dfs(a, i, j));
        return ans;
    }
};
```

时间 `O(mn)`，记忆表 `O(mn)`，递归栈最坏 `O(mn)`。工程环境栈较小时可考虑按值拓扑分层或显式栈。

## 10. 两数之和

```cpp
#include <iostream>
#include <unordered_map>
#include <vector>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, target;
    if (!(cin >> n >> target)) return 0;
    vector<int> a(n);
    unordered_map<int, int> pos;
    for (int i = 0; i < n; ++i) {
        cin >> a[i];
        auto it = pos.find(target - a[i]);
        if (it != pos.end()) {
            cout << it->second << ' ' << i << '\n';
            return 0;
        }
        pos[a[i]] = i;
    }
    cout << "-1 -1\n";
}
```

平均时间 `O(n)`、空间 `O(n)`；哈希最坏时间可能退化为 `O(n²)`。要确认返回下标还是数值、下标从0还是1开始、是否保证唯一解。

# 六、AI Coding 代码审查框架

面对 AI 生成的业务代码，不要只检查语法，按以下顺序回答：

1. **需求正确性**：输入、输出、状态机和错误码是否符合业务；

5. **实时性**：ISR是否过重、关键路径是否分配内存、是否有无界循环/阻塞；
6. **通信可靠性**：分包粘包、大小端、校验、序号、重试、幂等；
7. **可维护性**：模块边界、依赖方向、重复逻辑和测试接口；
8. **验证方案**：单测、故障注入、压力、竞态检测、性能数据。

口述模板：

> 我先确认代码是否满足业务状态机，再检查边界和失败路径；嵌入式场景重点看内存生命周期、ISR上下文、并发同步和超时恢复。然后用单测覆盖边界，用压力和故障注入验证竞态、断连与资源泄漏，最后再根据Profiling结果优化关键路径。

# 七、易错结论修正版

| 容易说错 | 更准确的说法 |
|---|---|
| `volatile` 能保证线程安全 | 不能；它不提供原子性、互斥和标准线程内存序 |
| ISR里可以直接用信号量 | ISR通常只能使用专用FromISR接口发送/释放，不能阻塞等待 |
| ISR里都能用自旋锁 | 取决于Linux/RTOS和上下文；必须用正确变体且临界区极短 |
| `const`大数组只占Flash、不占RAM | 典型MCU中常位于Flash只读段，但由平台和链接脚本决定 |
| 软件CS能解决GPIO数量不足 | 软件CS只改变控制方式；引脚不足仍需译码器/扩展器等 |
| PendSV在任务异常退出后触发 | PendSV用于延后执行上下文切换，可由调度请求触发 |

## 1. DMA 搬运什么数据，如何优化

### 面试简答

DMA让外设或内存控制器在较少CPU干预下搬运数据，常用于UART、SPI、I²C、ADC、音视频流、网卡收发以及内存到内存的大块数据传输。它搬运的是**字节/半字/字等原始数据块**，并不理解业务对象；源地址、目的地址、长度、方向和触发条件由CPU配置。

### DMA传输如何优化

1. **批量搬运**：合并小请求，减少DMA描述符配置和中断次数；
2. **双缓冲/环形缓冲**：DMA写一块时CPU处理另一块，重叠搬运与计算；
3. **Scatter-Gather**：使用描述符链搬运多个不连续缓冲区，减少CPU重新配置；
4. **对齐与Burst**：地址和长度满足总线对齐，使用较长Burst提高带宽利用率；
5. **减少拷贝**：DMA直接写入最终消费缓冲区，避免中间memcpy；
6. **缓存一致性**：非一致性系统在DMA前后正确clean/invalidate cache，使用内存屏障；
7. **控制中断频率**：按批次完成通知，不为每个小包触发一次中断；
8. **通道和优先级**：避免多个高带宽DMA长期争用同一总线。

### 是否必须攒很多数据再搬

不必须。大块DMA能摊薄启动成本，但会增加等待数据凑齐的延迟。实时业务应在吞吐和时延之间取平衡：控制命令和低延迟数据可使用小批次；图像、音频、网络包可使用环形缓冲和合理批量；非常短的数据有时CPU直接拷贝反而更快。

### 频繁搬运怎么办

先确认瓶颈是DMA启动、中断、总线还是缓存维护，再采用批处理、环形队列、零拷贝、Scatter-Gather、双缓冲和中断聚合。不能只盲目增大单次长度，否则可能破坏实时性。

## 2. 推理模型规模、图像预处理与低延迟

### 如何描述模型规模

不要只回答模型文件大小，应从四个维度回答：

- 参数量和权重精度，例如FP32/FP16/INT8；
- 输入Shape和Batch；
- 计算量，如FLOPs/MACs；
- 峰值内存，包括权重、激活、workspace和输入输出。

如果数字记不清，应说明测量工具和口径，不要临场编造。

### `640×640` 是缩放还是裁剪

取决于预处理实现，常见有三种：

1. 直接Resize到`640×640`，简单但会改变宽高比；
2. 等比例缩放后Letterbox补边，保持宽高比，是YOLO常见方案；
3. Resize后Center Crop/Random Crop，可能丢失边缘目标。

回答项目时必须与实际代码一致，并说明后处理是否把检测框映射回原图坐标。

### 为什么使用线程池

线程池复用固定数量工作线程，避免频繁创建销毁线程；还能限制并发量、通过任务队列实现生产者—消费者解耦，并减少线程过多造成的上下文切换和内存占用。线程数不是越多越好：CPU密集型通常参考可用核心数，I/O密集型可适当增加，并通过Profiling确定。

### 除线程池外如何降低推理延迟

- 模型侧：剪枝、量化、蒸馏、减小输入或轻量化网络；
- 图优化：常量折叠、算子融合、消除冗余格式转换；
- 内存侧：复用Buffer、零拷贝、预分配、Pinned Memory；
- 运行侧：异步流水、预处理/推理/后处理并行、合理Batch；
- 硬件侧：选择匹配的算子、数据格式和精度，减少Host—Device同步；
- 工程侧：先Profiling定位瓶颈，不能把所有慢都归因于模型。

### 推理代码从头写还是来自开源社区

建议按真实性分层回答：模型结构/权重来源、推理框架能力、自己开发的预处理/后处理/调度/部署适配分别是什么。可表述为：

> 底层推理能力基于___框架，我没有重复实现整个推理引擎；我负责的是模型转换、输入输出适配、预后处理、异步调度和性能优化，并通过___验证精度与时延。

## 3. Linux Kernel由哪些部分组成

### 面试简答

Linux是宏内核，核心子系统包括：

- 中断、时钟和同步机制；

它们运行在内核态，但通过系统调用向用户态提供受控服务。

## 4. 系统调用的完整过程

以Linux为例：

```text
用户程序调用libc封装函数
→ 将系统调用号和参数放入规定寄存器
→ 执行syscall/svc等陷入指令
→ CPU切换到内核态并进入系统调用入口
→ 保存用户态上下文，校验调用号和用户指针
→ 分发到具体内核实现
→ 得到返回值或错误码
→ 恢复上下文并返回用户态
```

系统调用不等于普通函数调用：它涉及特权级切换、参数安全检查，必要时还可能阻塞并触发调度。现代系统通常通过VDSO在用户态完成部分只读服务，以避免不必要的陷入。

## 5. Linux进程和线程如何管理

Linux内核用`task_struct`描述调度实体，进程和线程在内核中都表现为task。创建时通过`clone`系列机制选择共享哪些资源：同一线程组通常共享地址空间、文件表和信号处理等资源，但每个线程有独立调度状态、内核栈和用户栈。

常见关系：

- PID标识具体任务，TGID标识线程组；
- 调度器以可运行task为单位调度；
- `mm_struct`描述地址空间；
- 文件、信号处理等通过引用计数对象共享；
- task通过就绪队列、等待队列和各种链表/树结构组织。

## 6. 常见进程调度算法

| 算法 | 特点 | 主要问题/场景 |
|---|---|---|
| FCFS | 先来先服务，实现简单 | 长任务会阻塞短任务 |
| SJF/SRTF | 短任务优先，平均等待时间低 | 难以准确预测运行时间，长任务可能饥饿 |
| 时间片轮转 | 同优先级任务轮流运行 | 时间片过小切换多，过大退化为FCFS |
| 优先级调度 | 高优先级先运行 | 低优先级可能饥饿，可用老化缓解 |
| 多级反馈队列 | 根据行为动态调整队列 | 策略复杂 |
| EDF | 截止期最早优先 | 常见动态实时调度思想 |
| Rate Monotonic | 周期越短优先级越高 | 固定优先级实时任务 |

Linux普通任务由CFS/EEVDF等公平调度机制管理（取决于内核版本），实时策略包括`SCHED_FIFO`和`SCHED_RR`。

### Linux normal任务与FIFO任务关系

- 普通任务使用`SCHED_NORMAL`等公平调度策略；
- `SCHED_FIFO`属于实时策略，静态优先级高于普通任务；
- 同优先级FIFO任务不会因为时间片到期自动轮转，通常运行到阻塞、主动让出或被更高优先级任务抢占；
- 错误的高优先级FIFO线程可能长期压制普通任务，因此必须避免无界循环并配置资源限制。

### RTOS采用什么调度

FreeRTOS典型配置采用固定优先级抢占调度：最高优先级Ready任务运行；同优先级可按配置进行时间片轮转。任务阻塞、唤醒、更高优先级任务就绪或主动让出都会触发调度。

## 7. Buddy、Slab与内存碎片整理

### Buddy伙伴系统

Buddy按`2^order`个连续页管理物理内存。申请时把大块不断二分，释放时若伙伴块空闲则逐级合并。优点是合并快并能提供连续页；缺点是按2的幂分配会产生内部碎片。

### Slab/SLUB

Slab类分配器建立特定对象大小的缓存，从页中切出多个对象槽，复用已初始化对象，降低小对象频繁申请释放的开销和外部碎片。现代Linux常用SLUB实现。关系可概括为：

```text
伙伴系统管理“页”
→ Slab/SLUB从伙伴系统取得页
→ 再为内核分配小对象
```

### 常见碎片处理算法/方法

- 相邻空闲块合并、边界标记；
- First Fit、Best Fit、Next Fit等空闲块选择；
- Buddy快速拆分合并连续页；
- Slab/对象池按尺寸分类复用小对象；
- 内存压缩将可移动页迁移，形成连续空间；
- 页面回收、交换和大页整理；
- 嵌入式使用固定块内存池、静态分配和区域分配器。

外部碎片无法仅靠“统计空闲总量”解决，必须关注最大连续空闲块和对象是否可移动。

## 8. 内核态与用户态通过什么接口通信

| 接口 | 典型用途 |
|---|---|
| 系统调用 | 用户态请求内核服务的基础入口 |
| `read/write/ioctl` | 字符设备数据和控制命令 |

## 9. ROS、RTOS和Linux区别

这三个概念不在同一层级：

- **Linux**是通用操作系统内核及生态；
- **RTOS**是强调确定性调度和实时响应的一类操作系统；
- **ROS**是机器人软件中间件和工具生态，提供节点、Topic、Service、Action、消息和工具，通常运行在Linux等操作系统之上；ROS 2也可通过micro-ROS连接RTOS MCU。

## 10. RPC、Protobuf与蓝牙协议栈

### RPC是什么

RPC让调用方像调用本地函数一样请求另一个进程或设备执行服务。基本链路是：客户端Stub序列化参数，传输层发送，服务端Stub反序列化并调用实现，再把结果返回。工程上还要处理超时、重试、幂等、服务发现、版本兼容和部分失败。

### Protobuf的作用

Protobuf通过`.proto`定义结构化消息和字段编号，再生成多语言代码，提供紧凑二进制序列化。优势是跨语言、体积小、解析快和较好的前后兼容性；它只解决数据表示，不负责连接、传输、重试和服务治理。

### 蓝牙协议栈框架

可先分为控制器和主机两部分：

```text
应用/Profile
→ GATT/GAP等上层协议
→ ATT、SMP、L2CAP
→ HCI
→ Link Layer/Baseband/PHY
```

- Controller负责射频、基带和链路层时序；
- Host负责连接管理、数据复用、安全和属性协议；
- HCI连接Host和Controller；
- BLE中GAP负责发现、广播和连接角色，GATT/ATT负责基于Service和Characteristic的数据访问。

# 十、图片补充手撕题

## 1. 当前数字右侧第一个更大元素

使用单调递减栈。遍历到更大的值时，当前值就是栈顶元素的下一个更大值。

```cpp
#include <iostream>
#include <stack>
#include <vector>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n;
    cin >> n;
    vector<int> a(n), ans(n, -1);
    stack<int> st; // 保存尚未找到答案的下标，对应值单调递减
    for (int i = 0; i < n; ++i) {
        cin >> a[i];
        while (!st.empty() && a[i] > a[st.top()]) {
            ans[st.top()] = a[i];
            st.pop();
        }
        st.push(i);
    }
    for (int i = 0; i < n; ++i)
        cout << ans[i] << (i + 1 == n ? '\n' : ' ');
}
```

时间`O(n)`，空间`O(n)`；每个下标最多入栈、出栈一次。

## 2. 通配符匹配

假设`?`匹配任意单字符，`*`匹配任意长度字符串。使用贪心记录最近一个`*`及其目前匹配到的位置；失配时让该`*`多吞一个字符。

```cpp
#include <iostream>
#include <string>
using namespace std;

bool isMatch(const string& s, const string& p) {
    size_t i = 0, j = 0;
    size_t star = string::npos, match = 0;
    while (i < s.size()) {
        if (j < p.size() && (p[j] == '?' || p[j] == s[i])) {
            ++i; ++j;
        } else if (j < p.size() && p[j] == '*') {
            star = j++;
            match = i;
        } else if (star != string::npos) {
            j = star + 1;
            i = ++match;
        } else {
            return false;
        }
    }
    while (j < p.size() && p[j] == '*') ++j;
    return j == p.size();
}

int main() {
    string s, p;
    cin >> s >> p;
    cout << (isMatch(s, p) ? "true" : "false") << '\n';
}
```

典型情况下时间`O(m+n)`、空间`O(1)`；应先与面试官确认通配符语义。

## 3. LeetCode小于等于n的最大数（给定数字集合）

图片题意较简略，常见版本是：给定可重复使用的数字集合，组成不大于`n`的最大整数。核心方法是**数位贪心+回退**：从高位开始选不超过目标位的最大数字；若后续无法构造，就回退到前一位换更小数字，剩余位置全部填最大数字。面试前要确认：能否重复、是否包含0、能否有前导0，以及返回数值还是字符串。

## 4. 股票一次交易与无限次交易

### 一次交易

维护历史最低价格和当前最大利润：

```cpp
int maxProfitOnce(const vector<int>& p) {
    int minPrice = INT_MAX, ans = 0;
    for (int x : p) {
        minPrice = min(minPrice, x);
        ans = max(ans, x - minPrice);
    }
    return ans;
}
```

### 无限次交易

把所有相邻上涨都计入：

```cpp
int maxProfitUnlimited(const vector<int>& p) {
    int ans = 0;
    for (int i = 1; i < static_cast<int>(p.size()); ++i)
        ans += max(0, p[i] - p[i - 1]);
    return ans;
}
```

两者时间`O(n)`、额外空间`O(1)`。需要确认是否有手续费、冷冻期和持仓数量限制。

## 5. 最长回文子串

从每个位置向两侧扩展，分别处理奇数和偶数中心：

```cpp
#include <iostream>
#include <string>
using namespace std;

string longestPalindrome(const string& s) {
    if (s.empty()) return "";
    int bestL = 0, bestLen = 1;
    auto expand = [&](int l, int r) {
        while (l >= 0 && r < static_cast<int>(s.size()) && s[l] == s[r]) {
            if (r - l + 1 > bestLen) {
                bestL = l;
                bestLen = r - l + 1;
            }
            --l; ++r;
        }
    };
    for (int i = 0; i < static_cast<int>(s.size()); ++i) {
        expand(i, i);
        expand(i, i + 1);
    }
    return s.substr(bestL, bestLen);
}

int main() {
    string s;
    cin >> s;
    cout << longestPalindrome(s) << '\n';
}
```

时间`O(n²)`、额外空间`O(1)`。若追问最优时间，可介绍Manacher算法`O(n)`，但面试中中心扩展更容易写对。
