# LeetCode 153. 寻找旋转排序数组中的最小值 —— 学习笔记

> **题目**: [153. Find Minimum in Rotated Sorted Array](https://leetcode.cn/problems/find-minimum-in-rotated-sorted-array/)  
> **核心**: 已知一个长度为 `n` 的数组，预先按照**升序排列**，经 `1` 到 `n` 次**旋转**后，得到输入数组。找出数组中的**最小元素**。  
> **示例**:  
> ```
> nums = [3, 4, 5, 1, 2]     →  1
> nums = [4, 5, 6, 7, 0, 1, 2] →  0
> nums = [11, 13, 15, 17]    →  11（无旋转，原数组就是有序的）
> ```

---

## 一、核心思想：最小值就是"旋转点"

### 1.1 旋转数组的结构
原数组升序，旋转后形成两段递增序列，中间有一个"断崖"：

```
原数组: [0, 1, 2, 4, 5, 6, 7]
旋转后: [4, 5, 6, 7, 0, 1, 2]
              ↑
            断崖点（最小值 0 在这里）
        └─────┘  └─────┘
         大段     小段
        递增     递增
```

**关键性质**：
- 最小值是**唯一一个比它左边元素小**的元素（旋转点）；
- 以最小值为界，左边所有元素 `>= nums[0]`，右边所有元素 `< nums[0]`；
- 整个数组中**只有最小值这一个"谷底"**。

### 1.2 为什么可以用二分？
和 LeetCode 33 一样，旋转数组以 `mid` 为界，**必有一半是有序的**。利用有序半的端点值，可以判断最小值在哪一半。

## 二、代码实现（带完整注释）

```cpp
class Solution {
public:
    int findMin(vector<int>& nums) {
        // 初始化答案为一个极大值，用于记录遍历过程中遇到的最小候选
        int ans = 1e9;

        int l = 0, r = nums.size() - 1;     // 闭区间 [l, r]

        while (l <= r) {
            int mid = l + (r - l) / 2;       // 计算中点（防溢出）

            // ========== 情况1：左半部分 [l, mid] 是有序的 ==========
            // 判断依据：nums[l] <= nums[mid]，说明从 l 到 mid 单调递增，没有旋转点
            if (nums[l] <= nums[mid]) {
                // 左半有序，则 nums[l] 是左半部分的最小值
                // 它可能是全局最小值（比如数组无旋转时），所以先记录下来
                ans = min(ans, nums[l]);

                // 最小值不可能在左半部分的内部（因为左半递增，nums[l] 已经是最左最小）
                // 最小值要么在右半部分，要么已经被 ans 记录
                // 因此舍弃左半，去右半部分继续查找
                l = mid + 1;
            }

            // ========== 情况2：右半部分 [mid, r] 是有序的 ==========
            // 判断依据：nums[l] > nums[mid]，说明旋转点在左半部分
            else {
                // 右半有序，则 nums[mid] 是右半部分的最小值
                // 它可能是全局最小值，先记录下来
                ans = min(ans, nums[mid]);

                // 最小值不可能在右半部分的内部（因为右半递增，nums[mid] 已经是最右最小）
                // 最小值在左半部分（包含 mid 左侧的断崖区域）
                // 因此舍弃右半，去左半部分继续查找
                r = mid - 1;
            }
        }

        return ans;
    }
};
```

## 四、关键机制深度解析

### 4.1 为什么左半有序时，最小值不可能在左半内部？

```
[4, 5, 6, 7, 0, 1, 2]
 └─────┘
  左半有序 [4,5,6,7]
```

如果 `nums[l] <= nums[mid]`，说明 `[l, mid]` 是严格递增的（无旋转点）。那么：
- `nums[l]` 是左半部分的最小值；
- 左半部分的所有元素都 `>= nums[l]`；
- 全局最小值要么已经被 `nums[l]` 代表了，要么在右半部分。

因此可以**安全地记录 `nums[l]`，然后舍弃左半**。

### 4.2 为什么右半有序时，最小值在左半部分？

```
[6, 7, 0, 1, 2, 4, 5]
 └─────┘
  左半无序 [6,7,0,1]
```

如果 `nums[l] > nums[mid]`，说明 `[l, mid]` 跨越了旋转点（存在断崖）。那么：
- 旋转点（最小值）一定在 `[l, mid]` 范围内；
- 右半部分 `[mid, r]` 是有序的，`nums[mid]` 是右半的最小值；
- 但右半的最小值不一定是最小值，因为左半还有更小的。

因此记录 `nums[mid]` 作为候选，然后**去左半继续查找**。

### 4.3 为什么需要 `ans` 变量，不能直接返回？

因为二分过程中，**最小值可能在某一轮被"路过"**。例如：

```
[3, 4, 5, 1, 2]
```

第 1 轮：`l=0, mid=2`，左半有序，记录 `ans=3`，然后 `l=3`。
第 2 轮：`l=3, mid=3`，左半有序，记录 `ans=min(3, 1)=1`，然后 `l=4`。

如果第 1 轮直接返回 `nums[l]=3`，就错了！因为真正的最小值 `1` 还在右半部分等待被发现。

所以需要 `ans` 持续记录遇到的最小候选，直到搜索范围为空。

### 4.4 与 LeetCode 33（搜索旋转数组）的对比

| 对比项 | LeetCode 33（搜索 target） | LeetCode 153（找最小值） |
|:------:|:-------------------------:|:-----------------------:|
| **目标** | 找特定值 target | 找最小值（不知道具体值） |
| **命中处理** | `nums[mid]==target` 直接返回 | 没有"命中"概念，持续更新 ans |
| **有序半利用** | 判断 target 是否在有序半范围内 | 有序半的端点就是候选最小值 |
| **收缩策略** | 根据 target 位置决定去左/右 | 左半有序则去右，左半无序则去左 |
| **返回值** | 索引或 -1 | 最小值本身 |

## 五、更简洁的写法（不维护 ans）

其实这道题有更简洁的写法，不需要 `ans` 变量：

```cpp
class Solution {
public:
    int findMin(vector<int>& nums) {
        int l = 0, r = nums.size() - 1;

        while (l < r) {                     // 注意：这里是 < 不是 <=
            int mid = l + (r - l) / 2;

            if (nums[mid] > nums[r]) {
                // mid 比右端大，说明旋转点在右半，最小值在 (mid, r]
                l = mid + 1;
            }
            else if (nums[mid] < nums[r]) {
                // mid 比右端小，说明旋转点在左半或就是 mid，最小值在 [l, mid]
                r = mid;
            }
            else {
                // nums[mid] == nums[r]，无法判断，缩边（本题元素互异，不会出现）
                r--;
            }
        }

        return nums[l];  // l == r，唯一剩余元素就是最小值
    }
};
```

**为什么这种写法更简洁？**
- 直接与 `nums[r]` 比较，不需要维护 `ans`；
- 循环结束时 `l == r`，`nums[l]` 就是最小值；
- 但逻辑上不如你的写法直观（需要理解为什么与 `nums[r]` 比较）。

**你的写法的优势**：
- 逻辑清晰，每一步都明确"哪半有序"；
- 与 LeetCode 33 的解题框架一致，便于记忆；
- `ans` 变量的存在让"记录候选"的过程显式化。

## 七、易错点与面试 Tips

### ❌ 错误 1：左半有序时记录 `nums[mid]` 而不是 `nums[l]`
```cpp
// 错误
ans = min(ans, nums[mid]);  // ❌ nums[mid] 不是左半最小值，nums[l] 才是

// 正确
ans = min(ans, nums[l]);    // ✅ 左半有序，左端点就是左半最小值
```

### ❌ 错误 2：左半有序时去左半继续查找
```cpp
// 错误
r = mid - 1;  // ❌ 左半已经有序，最小值不可能在左半内部

// 正确
l = mid + 1;  // ✅ 去右半查找
```

### ❌ 错误 3：忘记初始化 ans
```cpp
int ans;  // ❌ 未初始化，可能是随机值
int ans = INT_MAX;  // ✅ 或 1e9
```

### ❌ 错误 4：`mid` 计算溢出
```cpp
int mid = (l + r) / 2;  // 不推荐
int mid = l + (r - l) / 2;  // ✅
```

### ❌ 错误 5：右半有序时记录 `nums[r]` 而不是 `nums[mid]`
```cpp
// 错误
ans = min(ans, nums[r]);  // ❌ 右半有序时，nums[mid] 才是右半最小值

// 正确
ans = min(ans, nums[mid]);  // ✅
```

### ✅ 面试回答框架
1. **思路**：旋转数组中必有一半有序；左半有序则左端点是候选最小值，去右半继续找；左半无序则右半有序，`nums[mid]` 是候选，去左半继续找；
2. **关键**：用 `ans` 持续记录遇到的最小候选，不能找到就停；
3. **复杂度**：时间 $O(\log n)$，空间 $O(1)$；
4. **扩展**：如果数组有重复元素（LeetCode 154），需要处理 `nums[mid] == nums[r]` 的歧义情况。

### ✅ 追问准备
- **问**：如果数组中有重复元素怎么办？  
  **答**：这就是 LeetCode 154。当 `nums[mid] == nums[r]` 时无法判断旋转点在哪，需要 `r--` 缩边，最坏退化到 $O(n)$。

- **问**：能不能直接返回 `nums[l]` 当左半有序时？  
  **答**：不能。因为最小值可能在右半部分（比如 `[4,5,6,7,0,1,2]`，`nums[0]=4` 不是最小值）。

## 八、一句话总结

> **旋转数组里最小值就是"断崖点"，它躲在有序半的对面。左半有序？那最小值肯定不在左半（左端点先记下来），去右边接着找。左半无序？那旋转点就在左半里（mid 先记下来），去左边接着刨。一路刨一路记，最后 ans 里存的就是最小值。**

| 要点 | 内容 |
|------|------|
| 核心策略 | 判断哪半有序 → 记录有序半的端点作为候选 → 去另一半继续找 |
| 左半有序 | `nums[l] <= nums[mid]`，记录 `nums[l]`，去右半 `l = mid + 1` |
| 左半无序 | `nums[l] > nums[mid]`，记录 `nums[mid]`，去左半 `r = mid - 1` |
| 为什么记端点 | 有序半的端点就是该半的最小值，是全局最小值的候选 |
| 为什么需要 ans | 最小值可能在搜索过程中被"路过"，需要持续更新 |
| 时间复杂度 | $O(\log n)$ |
| 空间复杂度 | $O(1)$ |
