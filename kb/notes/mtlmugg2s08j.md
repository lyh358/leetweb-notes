## 1. 手写环形缓冲区（FIFO 消息队列）⭐⭐⭐⭐⭐【最高频】

**适用场景：**裸机，单生产者、单消费者；例如中断写数据，主循环读数据**，非阻塞，不使用 RTOS 队列。** 

### **🗣️口述思路**：

> 我们用一块数组做存储，两个索引指针：`head`写指针、`tail`读指针。

1. 判断空：`head == tail`，代表缓冲区没有数据。
2. 判断满：**牺牲一个空位**，`(head+1)%BUF_SIZE == tail`代表缓冲区满。牺牲一个位置，用来区分满和空两种状态。
3. `head`、`tail`必须加`volatile`修饰：因为写指针会在中断中修改，防止编译器优化，保证主循环读到内存最新的值。
4. 入队 push：先判断是否满；不满就写入数据，更新 head。
5. 出队 pop：先判断是否为空；不为空读出数据，更新 tail。
6. 获取有效数据个数：通过 head、tail 相减取模得到。
7. 单生产者单消费者场景，不需要关中断临界区保护；如果多生产者就需要加临界区。

> 面试官高频追问： Q：为什么要 volatile？ A：变量在中断和主循环共享，volatile 阻止编译器把变量缓存到寄存器，每次都访问真实内存。 Q：为什么牺牲一个空位？ A：如果不牺牲空位，head 等于 tail 既可以代表空，也可以代表满，无法区分。

### 💻极简笔试代码

```
#include <stdint.h>

#define BUF_SIZE 64U //缓冲区大小：设置为64

//定义环形缓冲区结构体：开辟储存用缓冲+定义头尾指针
typedef struct {
    uint8_t buffer[BUF_SIZE];// 存储数据的缓冲区，uint8_t=1字节，环形缓冲区每个元素存1字节，所以数组类型用uint8_t
    volatile uint8_t head; // 写索引，8位（0‑255）也完全够表示 0~63的索引，够用。
    volatile uint8_t tail; // 读索引
} ringbuf_t;

// 初始化环形缓冲区
void ringbuf_init(ringbuf_t *rb)
{
    rb->head = 0U;
    rb->tail = 0U;
}

// 写入1字节，成功返回1，满返回0
int ringbuf_push(ringbuf_t *rb, uint8_t data)
{
    uint8_t next_head = (rb->head + 1U) % BUF_SIZE;
    if(next_head == rb->tail)
        return 0;

    rb->buffer[rb->head] = data;
    rb->head = next_head;
    return 1;
}

// 读取1字节，成功返回1，空返回0
int ringbuf_pop(ringbuf_t *rb, uint8_t *data)
{
    if(rb->head == rb->tail)
        return 0;

    *data = rb->buffer[rb->tail];
    rb->tail = (rb->tail + 1U) % BUF_SIZE;
    return 1;
}

// 获取当前有效数据数量
uint8_t ringbuf_count(ringbuf_t *rb)
{
    return (rb->head - rb->tail + BUF_SIZE) % BUF_SIZE;
}
```

#### ⚠️核心坑点小结（脑子里记住）

1. `volatile`不能丢；
2. 牺牲一个空位，最多存放`BUF_SIZE‑1`个字节；
3. 索引必须取模，防止越界；
4. 单生产单消费不用锁；多生产者必须临界区保护 head。

## **2. 实现 memmove（处理内存重叠拷贝）⭐⭐⭐⭐⭐**

### 🗣口述思路

> `memmove`功能：把 src 的 n 个字节拷贝到 dest，**重点支持内存区域重叠**，这是和`memcpy`最大区别。

1. 先判空指针，如果 dest 或者 src 为 NULL，直接返回 dest。
2. 把 dest、src 强制转换成`char* / const char*`，按字节进行处理。
3. 分两种拷贝方向：
   - 如果`dest <= src`：目标地址在源前面或者重合，**从前向后拷贝**，不会覆盖还没读取的源数据。
   - 如果`dest > src`：目标地址落在源内存的后方，存在内存重叠，**必须从后往前拷贝**，避免还未读取的源字节被提前覆盖。
4. 返回 dest 原始指针，和标准库行为保持一致。

> 高频追问：memcpy 和 memmove 区别？ memcpy 不处理内存重叠；当内存发生重叠时，memcpy 会覆盖源数据，结果未定义；memmove 区分拷贝方向安全处理重叠。

### 💻极简代码

```
#include <stddef.h>   // size_t

void* my_memmove(void *dest, const void *src, size_t n)
{
    // 空指针直接返回
    if(dest == NULL || src == NULL)	return dest;
    
    //memmove 要一个字节一个字节复制，每次搬运 1 字节
    //所以把任意类型的源指针和目标指针转换成char*
    char *d = (char *)dest;
    const char *s = (const char *)src;

    if(d <= s)
    {
        // 从前向后拷贝
        for(size_t i = 0; i < n; i++)
        {
            d[i] = s[i];
        }
    }
    else
    {
        // dest>src，存在重叠，从后往前拷贝
        for(size_t i = n; i > 0; i--)
        {
            d[i-1] = s[i-1];
        }
    }
    return dest;
}
```

### 拷贝方向判断逻辑

> d 是目标起始地址 `char *d = (char *)dest;` s 是源起始地址 `const char *s = (const char *)src;`

> 指针比较，比较的是**内存地址大小（内存编号）**。 地址数值越小 = 内存低地址；地址数值越大 = 内存高地址。

#### 1. `d <= s` → 从前向后拷贝（i 从 0 到 n‑1）

条件含义：**目标 dest 的起始地址 ≤ 源 src 起始地址**。 分两种子情况：

1. d < s：目标在源的**低地址方向**（dest 在 src 左边）
2. d == s：源和目标完全重合，拷贝等于什么都不做

这种情况，**从前向后拷贝安全**。

> 先复制低地址字节，再复制高地址字节；还没有读取过的源数据，都在更高地址，不会被覆盖。

内存示意图（d < s）

```
内存低地址 ---------------------------------->内存高地址
dest:   d[0] d[1] d[2]
src:          s[0] s[1] s[2] s[3]
```

dest 在 src 左边，从前往后复制，不会破坏还没读的 src 数据。

#### 2. `d > s` → 必须从后向前拷贝

> 目标 dest 起始地址，落在源 src 缓冲区的后面（d 的地址数字更大，dest 在 src 右边）。 此时发生**后向重叠**，如果从前向后拷贝，会把还没读取的 src 字节提前覆盖掉。

例子，发生重叠：

```
src:  s0 s1 s2 s3 s4
dest:     d0 d1 d2 d3 d4
```

d > s，dest 的起始地址在 src 中间。 如果从前向后复制： 先写 d0 = s0，这就把原来的`s1`给覆盖破坏了，后面读 s1 就读到错误数据。

✅解决：**从后往前拷贝**，先复制高地址字节，再复制低地址字节。 先处理靠后的字节，就不会把还没读的数据覆盖。

循环写法：

```
for(size_t i = n; i > 0; i--)
{
    d[i-1] = s[i-1];
}
```

先拷贝 `d[n‑1]=s[n‑1]`，再往前走到 0。

### ⚠️关键坑点

1. 参数类型：`n`必须是`size_t`（无符号），不要写 int。
2. `src`要加`const`，源内存不允许修改。
3. 两种拷贝方向不能写反；`dest>src`才后向拷贝。
4. 边界：`n == 0`，循环不会执行，函数直接返回，代码天然支持，不用额外 if 判断。
5. 返回值必须返回 dest 指针。

### 三种内存场景快速回忆

1. 完全无重叠：前后拷贝都可以，代码走从前向后。
2. dest 在 src 后面（重叠）：**必须从后往前拷贝**，防止源数据被覆盖。
3. dest 在 src 前面（重叠）：从前向后拷贝安全。

## **3. 判断大小端序 ⭐⭐⭐⭐**

### 思路叙述

#### 背景概念

1. 对于`unsigned int val = 0x00000001`（4 字节）：

- 数字的**低字节**：`0x01`（数值权重最小）
- 数字的**高字节**：`0x00 0x00 0x00`（数值权重大）

1. 内存地址：内存编号小叫**低地址**；内存编号大叫**高地址**。
2. 大小端定义：

- **小端模式**：内存**低地址存放数字的低字节**；STM32、ESP32、x86 都是小端。
- **大端模式**：内存**低地址存放数字的高字节**；网络通信默认大端，和人阅读十六进制书写顺序一致。

#### 检测原理

把 4 字节 int 变量的地址，强制转换成`char*`字符指针。

> `char*`指针指向变量的**起始内存（也就是最低地址）**，解引用`*p`只会读取低地址上的**1 个字节**。

- 如果`*p == 1`：低地址存放的是低字节`0x01` → **小端，返回 1**
- 如果`*p == 0`：低地址存放的是高字节`0x00`，`0x01`存放到高地址 → **大端，返回 0**

> 关键点：我们只看变量最开始的低地址这一个字节，就可以完成判断，不需要读取全部 4 字节。

#### 面试口述话术（可以直接说）

> “我定义一个 unsigned int 赋值为 1，这个数有效低字节是 0x01。把它的地址强转为 char*，char 指针指向变量起始的低地址，解引用拿到低地址的单字节。读到 1 说明低地址存低字节，是小端；读到 0 说明低地址存高字节，是大端。”

### 完整代码

```
/**
 * @brief 检测系统大小端
 * @retval 1：小端模式； 0：大端模式
 */
int main(void)
{
    // 4字节无符号整数，值为1，二进制：0x00000001
    unsigned int val = 1;

    // 取val的起始地址，强转为char*
    // char*指向变量的内存最低地址，解引用只读取1个字节
    unsigned char *p = (unsigned char *)&val;

    if (*p == 1)
    {
        // 低地址存放低字节0x01 → 小端
        return 1;
    }
    else
    {
        // 低地址存放高字节0x00 → 大端
        return 0;
    }
}
```

#### 易错点提醒

1. 不能强转回`int*`解引用，那样一次性读取 4 字节，无法判断存储顺序。
2. `char *p = (unsigned char *)&val;`，p 保存的是变量**起始最低地址**；想要访问后面字节需要写`*(p+1)`、`*(p+2)`。
3. 本题默认 int 占 4 字节，嵌入式笔试环境都是这个前提。
4. **用unsigned是为了避免最开始有符号位0/1干扰判断**

## **4. 位操作宏 SET_BIT / CLR_BIT / TOG_BIT ⭐⭐⭐⭐**

### 口述思路

> 用于对一个 32 位无符号整数的指定 bit 进行置 1、清 0、翻转，bit0 是最低位。

1. 置 1 用**按位或**|：把目标 bit 置 1，其余位保持不变；
2. 清 0 用**按位与 & 配合取反～**：把目标 bit 清零，其余位保持不变；
3. 翻转用**按位异或 ^**：该位 0 变 1、1 变 0，其他位不变。

重点注意两个坑：

1. **移位要用`1U`无符号数**，避免有符号数移位产生符号位的未定义行为；
2. **宏所有参数全部加括号**，防止**运算符优先级**带来**错误**；
3. 宏会直接修改传入的变量，**传入的 x 必须是左值**，不能传常量表达式。

### 极简代码

```
// 设置无符号整数x的第n位为1
#define SET_BIT(x, n)  ((x) |= (1U << (n)))
// 清除第n位为0
#define CLR_BIT(x, n)  ((x) &= ~(1U << (n)))
// 翻转第n位
#define TOG_BIT(x, n)  ((x) ^= (1U << (n)))
```

### 面试官高频追问

为什么用`1U`而不是`1`？

> `1`是有符号 int，如果移位到符号位，属于 C 语言未定义行为；`1U`无符号，移位行为确定安全。

宏里面每个参数为什么都套括号？

> 宏是文本直接替换，如果传入表达式，不加括号会被运算符优先级破坏逻辑。

## 5. 串口协议解析有限状态机⭐⭐⭐

帧格式：帧头 0xAA + 长度 N + N 字节数据 + 1 字节异或校验和。 **口述思路**：

> 串口是流式字节流，没有帧边界，用状态机逐字节处理。 4 个状态：IDLE 等待帧头、LEN 接收长度、DATA 接收数据、CHECKSUM 接收校验字节。 IDLE 检测帧头 0xAA；拿到长度后把长度字节参与校验；逐个接收数据并存入缓冲区，每个数据字节更新校验；收完数据接收校验字节。 校验匹配成功调用上层回调；无论校验对错，回到 IDLE，准备下一帧，实现帧同步容错。

**踩坑点**

1. 忘记**长度字节也要参与异或校验**；
2. 出错之后不切回 IDLE，状态卡死。

## 6.实现strlen、strcpy、strncpy

### 6‑1 my_strlen

**🗣面试口述简述**

> strlen 计算字符串有效长度，不包含末尾`'\0'`。 入参是 const char*，字符串只读。指针向后遍历，直到遇到`\0`结束，统计字符个数。要做空指针判断。

```
#include <stddef.h>
size_t my_strlen(const char *s)
{
    if(s == NULL)
        return 0;
    size_t len = 0;
    while(*s != '\0')
    {
        len++;
        s++;
    }
    return len;
}
```

### 6‑2 my_strcpy

**🗣面试口述简述**

> strcpy 把源字符串拷贝到目标缓冲区，会把结束符`\0`也拷贝过去。 src 源字符串 const 只读；循环逐个字节复制，直到把`'\0'`拷贝完成。 风险：不检查目标缓冲区大小，如果源字符串过长，会内存越界。

```
char *my_strcpy(char *dest, const char *src)
{
    char *p = dest;
    if(dest == NULL || src == NULL)
        return dest;
    while((*p++ = *src++) != '\0')
    {
        ;
    }
    return dest;
}
```

### 6‑3 my_strncpy

**🗣面试口述简述**

> strncpy 最多拷贝 n 个字节。拷贝 n 个字节或者遇到源串`\0`就停止。 ⚠️重要坑：如果源字符串长度大于等于 n，**不会自动补`'\0'`，字符串没有结束符，会造成乱码**。这是它的典型缺陷。

```
char *my_strncpy(char *dest, const char *src, size_t n)
{
    char *p = dest;
    if(dest == NULL || src == NULL)
        return dest;
    while(n > 0 && (*src != '\0'))
    {
        *p++ = *src++;
        n--;
    }
    // 剩余字节填0
    while(n > 0)
    {
        *p++ = '\0';
        n--;
    }
    return dest;
}
```

> 追问点：strncpy 的坑：源串 >=n 时，不会自动追加`\0`，使用时需要手动给末尾补零。

## 7. CRC8 简单实现（CRC‑8‑MAXIM，嵌入式常用）

**🗣面试口述简述**

> CRC 是循环冗余校验，用于通信数据检错。 1. 初始化 crc 初始值； 2. 遍历输入每一个数据字节； 3. 每个字节和当前 crc 异或；逐 bit 移位，若最高位为 1 和多项式异或； 4. 全部字节处理完返回 crc 结果。 CRC16 逻辑流程完全一样，只是位宽、多项式、初始值不同。

```
#include <stdint.h>

// CRC8‑MAXIM 多项式 0x31
uint8_t crc8(const uint8_t *buf, uint16_t len)
{
    uint8_t crc = 0x00;
    for(uint16_t i = 0; i < len; i++)
    {
        crc ^= buf[i];
        for(uint8_t bit = 0; bit < 8; bit++)
        {
            if(crc & 0x80U)
            {
                crc = (crc << 1U) ^ 0x31U;
            }
            else
            {
                crc = crc << 1U;
            }
        }
    }
    return crc;
}
```

> 补充口述：工程一般预计算 CRC 查表提升速度；笔试一般写逐位计算版本。

## 8. 裸机双向循环链表：节点插入、删除

> RTOS 队列底层就是双向链表；校招很少完整手写，大概率口述思路。

**🗣面试口述简述**

> 双向循环链表，每个节点有 prev 前驱、next 后继指针。整个链表首尾相连，尾节点 next 指向头；头节点 prev 指向尾。 插入：修改 4 个指针：新节点的 prev、next，相邻两个节点的 next、prev。 删除：把待删节点的前后两个节点互相链接。 需要处理边界：链表为空、只有一个节点的情况。 注意：不要丢失指针，造成内存泄漏。嵌入式裸机一般不做 malloc，节点是静态定义。

```
#include <stdint.h>

typedef struct node
{
    int data;
    struct node *prev;
    struct node *next;
} node_t;

// 在pos节点后面插入new_node
void list_insert_after(node_t *pos, node_t *new_node)
{
    new_node->next = pos->next;
    new_node->prev = pos;
    pos->next->prev = new_node;
    pos->next = new_node;
}

// 删除节点del_node
void list_remove(node_t *del_node)
{
    del_node->prev->next = del_node->next;
    del_node->next->prev = del_node->prev;
    // 清空被删节点指针，防止野指针
    del_node->prev = NULL;
    del_node->next = NULL;
}
```

> ⚠️面试追问要点： 1. 双向循环链表插入删除，要修改 4 处指针； 2. 删除时，不需要传头指针，双向链表可以自己找到前后节点； 3. 注意空链表、链表只有一个节点的边界情况。

>场景：面试官口头提问、机考简答、找bug题口述分析，语言简短，适合口头表达。

## 1.`uint8_t` / `uint16_t` / `uint32_t` 

头文件：`#include <stdint.h>`，这是 C99 标准引入的固定宽度整数类型。

| 类型       | 含义                 | 大小           | 范围           |
| ---------- | -------------------- | -------------- | -------------- |
| `uint8_t`  | unsigned int 8 bits  | 1 字节 (8bit)  | 0 ~ 255        |
| `uint16_t` | unsigned int 16 bits | 2 字节 (16bit) | 0 ~ 65535      |
| `uint32_t` | unsigned int 32 bits | 4 字节 (32bit) | 0 ~ 4294967295 |

`u` = unsigned 无符号；数字代表比特位数；`_t`代表 type（类型）。

### 关键问题：为什么嵌入式优先用这套，不直接用 `int`、`short`、`long`？

#### 1️⃣ `int` 的字节宽度**是不标准的，平台会变**

如果你写 `uint16_t a;`，**无论什么 MCU，一定占 2 个字节**。 

如果你写 `int a;`，换个芯片，大小可能直接改变，代码就出 bug。

#### 2️⃣ 寄存器、硬件外设都是固定 bit 位

单片机外设寄存器：8 位、16 位、32 位硬件寄存器。 比如一个 32 位的外设寄存器，就用`uint32_t`；8 位 IO 寄存器就用`uint8_t`。 和硬件寄存器位数一一对应，语义清晰。

#### 3️⃣ 无符号类型更适合：计数、缓冲区索引、位操作

 `uint8_t / uint16_t / uint32_t`无符号，不会出现负数、符号位扩展问题。

> 之前大小端代码，环形缓冲区 head/tail，全部用`uint16_t`就是这个道理。

#### 4️⃣ 那什么时候才可以用普通 int？

普通`int`不是不能用： 业务逻辑里面做普通循环、局部临时计算，确定平台不会移植，可以用`int`。 **但是涉及硬件、协议、缓冲区、寄存器、跨平台代码，一律用 stdint.h 固定宽度类型。**

## C语言相关（5）

### 1. 结构体字节对齐、如何取消字节填充⭐⭐⭐⭐⭐

**面试官常见问法** 1）结构体为什么sizeof算出来比所有成员加起来大？ 2）怎么取消结构体的字节填充？这么做有什么风险？

✅口述回答：

> C语言结构体默认开启字节对齐。两点规则：第一，每个成员要存放在自身大小整数倍的地址上，编译器会自动插入padding填充字节；第二，结构体整体大小，必须是内部最大成员的整数倍。对齐是为了适配CPU硬件访问，提升读写效率。
>
> **取消字节填充有两种常用方式：** 第一种使用预处理指令 `#pragma pack(1)`，把对齐边界设置为1字节，编译器就不再插入padding填充；用完之后要用`#pragma pack()`恢复默认对齐。 第二种使用GCC编译器扩展属性 `__attribute__((packed))` 修饰结构体，直接取消该结构体内部所有填充字节。
>
> 取消填充之后结构体内存占用变小，但会带来**非对齐访问**风险。部分Cortex‑M芯片遇到非对齐访问会直接触发HardFault硬件异常，程序死机，这是最主要隐患。

记忆要点：对齐为CPU访问效率；`#pragma pack(1)` / `__attribute__((packed))`取消填充；会产生非对齐访问HardFault风险。

### 2. 有符号数和无符号数隐式转换

**面试官常见问法** 1）有符号int和unsigned无符号数一起运算会发生什么？ 2）`if(-1 > sizeof(int))`这个判断为什么结果是true？

✅口述回答：

> C语言规则，当有符号类型和无符号类型做运算、比较的时候，**有符号数会隐式转换成无符号数**。 负数转成无符号之后，会变成一个非常大的正数。 比如`sizeof`返回size_t是无符号，‑1被转成很大的无符号值，所以‑1大于sizeof(int)条件成立，逻辑和人的直觉相反。写代码要尽量避免有无符号混合比较。

记忆要点：**有符号 → 转无符号；负数变超大正数，判断逻辑错乱。**

---



### 3. 宏的副作用

**面试官常见问法** 1）宏和函数有什么区别？ 2）为什么宏里面传i++会出问题？参数全部加括号为什么还救不了？

✅口述回答：

> 宏是预处理阶段直接文本替换，不是函数调用，没有参数拷贝。 就算每个参数都加上括号，如果传入自增、自减这类表达式，表达式会被替换展开执行多次，产生副作用。 参数加括号只能解决运算符优先级问题，**无法解决多次执行带来的副作用问题**，这种场景尽量用inline内联函数代替宏。

记忆要点：文本替换，会多次执行表达式；括号解决优先级，解决不了副作用。

---



### 4. 悬空指针，不能返回局部栈变量地址

**面试官常见问法** 1）这个函数返回局部数组的指针，会有什么问题？ 2）局部变量和static局部变量区别，哪个可以返回地址？

✅口述回答：

> 函数内部普通局部变量、局部数组存放在栈内存。函数执行结束之后，栈内存会被回收复写。 如果返回它的地址，外部拿到的就是悬空指针，指向已经失效的内存，访问会产生随机bug、崩溃。 如果局部变量加static，变量存放在静态数据区，函数结束内存不会释放，这种就可以返回地址。

记忆要点：普通局部在栈，不能返回地址；static局部在静态区，可以返回。

---



### 5. volatile关键字

**面试官常见问法** 1）volatile作用是什么，什么场景要用？ 2）环形缓冲区head、tail为什么加volatile，buffer数组为什么不加？

✅口述回答：

> volatile的作用是告诉编译器，这个变量不要做寄存器缓存优化，每次读写都必须真实访问内存。 两个典型使用场景：第一，硬件外设寄存器；第二，中断和主循环共享的全局变量。 拿环形缓冲区举例：head、tail会在中断修改，主循环读取，必须加volatile，防止编译器读到旧的缓存值。 而buffer数组不需要volatile，中断写head位置，主循环读tail位置，不会同时读写同一个数组元素，不存在跨域访问问题。 普通局部变量不需要加volatile。

记忆要点：阻止编译器缓存；硬件寄存器、中断共享变量使用；普通变量不要乱加。

## Cortex‑M 内核部分（4）

### 1. VTOR 向量表偏移寄存器

**常见提问**：VTOR 寄存器作用？什么时候要配置 VTOR？ ✅口述回答：

> VTOR 是向量表偏移寄存器，用来设置中断向量表在 Flash 或者 RAM 中的起始地址。 默认向量表从 0x0 地址开始。做**OTA 固件升级、bootloader 引导 App**的时候，App 的向量表不在 0 地址，启动 App 之后必须配置 VTOR，把向量表偏移到 App 自己的向量表起始地址，否则中断会跳转到 Bootloader 的中断服务函数，中断异常。

记忆点：改变中断向量表基地址；Bootloader‑App 场景必须配置。

------

### 2. PendSV 异常用途

**常见提问**：PendSV 是用来干嘛的？为什么任务切换要用 PendSV，不用普通 SysTick 中断做任务切换？ ✅口述回答：

> PendSV 是可挂起的系统异常，**专门用于 FreeRTOS 等 RTOS 的任务上下文切换**。 PendSV 特点：可以手动置位触发，并且它的优先级可以设为最低。 如果在 SysTick 中断里面直接做任务切换，假如此时正在处理其他高优先级中断，任务切换会打断中断处理，造成严重问题。 把任务切换放到优先级最低的 PendSV 中，只有所有其他中断全部处理完毕之后，才执行 PendSV，做任务切换，保证不会抢占正在执行的中断服务程序。

记忆点：RTOS 任务切换；优先级最低；等所有中断执行完再切换任务。

------

### 3. MSP / PSP 双栈指针（主栈、进程栈）

**常见提问**：MSP 和 PSP 区别？RTOS 下什么时候用 MSP，什么时候用 PSP？ ✅口述回答：

> Cortex‑M 有两个栈指针 MSP 主栈、PSP 进程栈，同一时刻只能使用其中一个。

1. **MSP (主栈)**：复位默认使用。异常、中断服务函数一律使用 MSP 栈。Boot、main 函数启动阶段默认用 MSP。
2. **PSP (进程栈)**：供 RTOS 普通任务线程使用。每个任务拥有自己独立的 PSP 任务栈。

> RTOS 运行后：任务里面跑用户代码使用 PSP；一旦进入中断 / 异常，硬件自动切到 MSP；中断退出回到任务，又切回 PSP。 好处：各个任务栈互相独立，一个任务栈溢出不会破坏别的任务栈，中断使用独立主栈也不会被任务栈影响。

记忆点：中断 / 异常永远用 MSP；RTOS 任务用 PSP。

------

### 4. 异常自动压栈寄存器

**常见提问**：进入中断的时候，硬件自动压入哪些寄存器？ ✅口述回答：

> 当发生异常进入中断，CPU 硬件会自动把 8 个寄存器压入当前栈：`R0‑R3、R12、LR、PC、xPSR`。 剩下 R4~R11 这 8 个寄存器需要软件手动保存，RTOS 做任务上下文切换的时候，就是手动保存 / 恢复 R4‑R11。

记忆点：硬件自动压 8 个；R4‑R11 需要软件手动保存。

------



## FreeRTOS 高频问题（4）

### 1. FreeRTOS 的任务状态

**常见提问**：FreeRTOS 任务有哪几种状态，简单说下？ ✅口述回答： 一共 4 种基础状态：

1. **运行态 Running**：CPU 当前正在执行这个任务。同一时刻只有一个任务处于运行态。
2. **就绪态 Ready**：任务条件满足，可以运行，等待调度器分配 CPU 时间。
3. **阻塞态 Blocked**：任务等待事件，比如延时、信号量、队列等待，主动放弃 CPU，不会参与调度。
4. **挂起态 Suspended**：调用 vTaskSuspend 挂起任务，除非被唤醒，永远不参与调度。

> 区分：阻塞是等待某个事件；挂起是主动暂停，不等待任何事件。

记忆点：运行、就绪、阻塞、挂起。

------

### 2. 优先级反转

**常见提问**：什么是优先级反转？怎么解决？ ✅口述回答：

> 优先级反转：高优先级任务被低优先级任务阻塞，中间被一个中优先级任务抢占 CPU，导致高优先级任务迟迟得不到运行。 发生场景：低优先级任务拿到互斥锁，高优先级任务来获取同一个锁被阻塞；此时一个中等优先级任务就绪，抢占 CPU，低优先级拿不到 CPU，释放不了锁，高优先级就一直被卡住。 FreeRTOS 提供两种解决方案：**优先级继承、优先级天花板（优先级封顶）**。

记忆点：互斥锁引发；中优先级插队；解决：优先级继承、优先级天花板。

------

### 3. 临界区两种实现：关中断 vs 关闭调度器

**常见提问**：关中断和关调度器区别，分别保护什么场景？ ✅口述回答：

1. 关中断：屏蔽部分或者全部中断。任务和中断都无法抢占当前代码。

   - 适用场景：**任务与中断之间共享的资源保护**。
   - 缺点：关闭中断会影响系统实时性，关闭时间不能太长。

2. 关闭调度器（锁调度器）

   ：只是禁止任务切换，中断仍然可以正常响应执行。

   - 适用场景：**只在多个任务之间共享资源，没有中断访问该资源**。
   - 缺点：不能阻止中断修改共享变量。

> 总结：只要中断会访问共享资源，就必须关中断；只有任务之间访问，用关闭调度器即可。

记忆点：关中断 → 阻止任务 + 中断；关调度器 → 仅阻止任务切换，中断照常跑。

------

### 4. 中断里为什么要用 xxx_FromISR 版本 API

**常见提问**：中断中调用 FreeRTOSAPI 为什么要用带 FromISR 的函数？直接普通 API 会怎么样？ ✅口述回答：

> FreeRTOS 普通 API 函数会操作任务的栈、调度器，内部会触发任务切换，这些操作不能在中断上下文执行。 `xxx_FromISR`是专门给中断服务函数调用的版本，不会直接执行任务切换，只会标记是否需要上下文切换，通过参数`pxHigherPriorityTaskWoken`输出标记。 中断退出前，如果标记为 true，手动置位 PendSV，在离开中断之后再执行任务切换。 如果中断直接调用普通 API，会破坏内核，系统死机。

记忆点：普通 API 不能在中断调用；FromISR 版本不直接切换任务，标记标志，靠 PendSV 退出中断后再切换。

## 遗漏点 1：裸机 SysTick 软件定时器（无符号 tick 超时判断）⭐⭐⭐⭐

> 考察场景：简答题、代码找 bug、面试口述；极少完整手写整套驱动，常考**超时判断的坑**。

### 🗣面试口述思路

> 在裸机没有 RTOS 的环境下，我们利用 SysTick 硬件定时器，周期性中断维护一个全局的`tick`计数值，一般是毫秒单位，变量类型必须是**无符号 uint32_t**。 中断里面只做一件事：把全局 tick 变量自加，**中断里面不做延时、不执行业务逻辑**。业务的超时判断全部放在主循环 while (1) 里面执行。
>
> ⚠️核心坑点：不能直接写 `if(current_tick > expire_tick)` 判断超时。 因为 tick 是无符号，会溢出回绕。例如 tick 从很大值溢出变成 0，这个大于判断逻辑就失效。
>
> 正确的判断方式用**无符号减法**： `if( (current_tick - start_tick) >= delay_ms )` 无符号数减法硬件天然处理溢出回绕，就算 tick 发生溢出，判断依然正确。

> 使用流程：
>
> 1. 要开启延时的时候，记录下当前的`start_tick = g_tick`；
> 2. 在主循环不断判断上面的减法表达式；
> 3. 条件成立代表延时时间到，执行对应业务。

### 📝伪代码（笔试草稿可以写）

```
#include <stdint.h>
// 全局tick，SysTick中断每ms+1，无符号
volatile uint32_t g_tick = 0U;

// SysTick中断服务函数
void SysTick_Handler(void)
{
    g_tick++; // 只做计数，不做业务
}

int main(void)
{
    // 初始化systick
    SysTick_Init();
    uint32_t start_tick;
    while(1)
    {
        start_tick = g_tick;
        // 等待500ms超时
        if( (g_tick - start_tick) >= 500U )
        {
            // 执行超时业务
        }
    }
}
```

> 追问记忆点：
>
> 1. `g_tick`需要 volatile，因为中断修改、主循环读取；
> 2. 禁止用大于比较，必须用无符号减法；
> 3. 中断只计数，业务逻辑放主循环。

## 遗漏点 2：中断编写通用规范⭐⭐⭐⭐

> 出题形式：简答、选择题、找错题。不需要代码，纯口述。

### 🗣面试口述思路

> 写中断服务函数有几条核心规范：
>
> 1. **中断执行时间一定要尽可能短**，不要在中断里面做复杂运算、延时、循环等待。复杂业务数据，把数据扔给环形缓冲区 / 设置标记，交给主循环或者 RTOS 任务去处理。
> 2. 如果是 FreeRTOS 环境，中断里面调用内核 API，必须使用`xxx_FromISR`后缀版本，禁止直接调用普通任务 API，否则会破坏内核。
> 3. 中断内部不要调用 printf。printf 不可重入，多中断场景容易发生死锁。
> 4. 中断与主循环 / 任务共享的全局变量，需要加上`volatile`，防止编译器优化读取旧值。
> 5. 如果中断和任务会同时访问同一块共享资源，需要加临界区保护，比如关中断。

> 面试官如果追问风险，可以补充：
>
> > 如果中断耗时太长，会屏蔽其他中断，造成其他外设响应丢失，系统实时性变差。
