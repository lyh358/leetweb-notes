# 平头哥风格开放性技术问答（14 道，贴合你简历 + 芯片软件‑软硬件系统优化岗）

> 特点：**没有标准答案，考察分析思路、软硬件权衡、工程取舍、迁移思考**，和你之前华为实习面试遇到的开放题风格一致。
> 答题通用模板：现象→分析约束→多方案对比→权衡取舍→总结收获，尽量结合你简历里昇腾实习、电池部署、ReRAM 科研的真实经历举例，不要空谈理论。

## 基础认知｜软硬件协同 & 异构芯片理解

### Q1：你怎么理解软硬件协同优化？软件可以给硬件架构设计提供哪些反馈输入？

**回答：**
软硬件协同核心是**软件充分理解硬件微架构约束，同时软件侧的真实业务痛点反向指导硬件设计**，不是硬件做完软件被动适配。
软件侧可以给硬件提供几类输入：

1. 从 Profiling 统计真实业务算子特征：比如某些高频算子频繁做 Cast 类型转换，打断算子融合，那硬件可以增加混合精度原生支持；
2. 访存瓶颈：业务大量出现小粒度、不连续 DMA 搬运，片上 Buffer 大小不匹配业务 Tile 尺寸，可以反馈硬件调整存储层级、Buffer 大小；
3. 调度开销：大量小算子带来调度开销占比很高，可以建议硬件增加硬件加速指令或者扩展融合能力；
4. 容错 / 非理想特性：就像我 ReRAM 存内计算课题，器件存在故障变异，软件做补偿的代价很高，可以反馈硬件增加修复机制。
反过来软件要基于硬件 AI‑Core 算力、片上 SRAM、DMA 能力做 Tiling、算子融合、双缓冲，榨干硬件利用率。

### Q2：边缘 NPU（如昇腾 310P3）和数据中心 AI 芯片，做算子 / 模型优化，侧重点有什么不同？

**回答：**

1. 边缘侧：算力、片上内存、功耗受限；重点是单帧时延、功耗，要做极致图精简、静态 Shape、尽量减少片外访问；我的华为基站实习就是边缘场景，对单推理时延指标卡得很死。
2. 数据中心芯片：算力和内存更大，面向大模型、高吞吐 QPS；除单请求时延，更看重**整体吞吐量、多 batch、多并发、KV Cache 复用**；会遇到巨大中间张量，需要处理显存 / 内存压力、请求调度。
3. 相同点：底层方法论一致，都要 Profiling 定位访存 / 计算瓶颈、算子融合、Tiling 分片、计算访存流水掩盖延迟。
我的工程经验主要来自边缘，大模型并发吞吐这块工程经验不足，但优化方法论可以迁移，我也在阅读 vLLM 相关源码理解 KV Cache 等机制。

### Q3：做算子性能评估，你会建立一套什么样的评估指标体系？

**回答：**
分成硬件层、算子层、业务层三层。

1. 硬件层：AI‑Core 利用率、DMA 带宽利用率、片上 SRAM 占用、GM 带宽压力，看硬件资源有没有跑满；
2. 算子层：单算子时延，不同输入 shape 下性能、精度（误差、余弦相似度），不同精度模式 FP16/INT8 下性能‑精度曲线；
3. 业务层：端到端推理时延、计算图调度开销、多轮迭代场景下的内存反复分配释放开销。
同时要做对照组：原始版本作为基线，保证每一项优化都做优化前后对照；就像我华为实习建立的 Profiling‑优化‑实测‑精度验证闭环，不能只看时延，忽略精度退化。

## 围绕你的华为昇腾实习高频开放题

### Q4：你在 Transformer 优化中，Profiling 之后怎么判断瓶颈是计算瓶颈还是访存瓶颈？如果访存是瓶颈，你会从哪几个方向下手？

**回答：**
判断方法：看 AI‑Core 忙碌占比，如果 Core 大部分时间在等待数据，算力没跑满，就是访存瓶颈；如果 Core 持续高占用，时延主要消耗在计算，就是计算瓶颈。
我当时基站 Transformer 场景主要是**访存瓶颈**。
访存瓶颈的优化方向：

1. 算子融合：消除中间张量往全局内存写回；
2. Tiling 分片，尽量把计算所需数据放在片上 SRAM，减少 GM 读写；
3. Ping‑Pong 双缓冲，DMA 预取和计算流水并行，掩盖数据搬运延迟；
4. 图层面：常量折叠、消除冗余节点，减少不必要的数据生成与搬运。

### Q5：为什么算子融合可以提速？是不是算子融合越多一定越快？什么场景算子融合收益很低甚至负收益？

**回答：**
算子融合核心收益：**消除中间张量向全局内存的读写开销，不是减少计算量**。
但不是融合越多越好，有代价：

1. 融合之后中间张量需要全部放在片上 SRAM；如果融合后的中间数据超过片上缓存容量，会触发片上溢出，反而性能暴跌；
2. 部分算子融合后破坏硬件原有向量化调度，硬件利用率下降；
3. 我实习遇到的案例：引入 INT8 量化带来大量 Cast 算子，本意想做融合，但 Cast 算子反而打断原有融合链路，整体性能倒退。
所以要权衡：融合收益 vs 片上存储压力、硬件算子原生能力，需要实测验证，不能纸上推演。

### Q6：静态 Shape 对比动态 Shape，各自优缺点，什么场景你会主动选静态 Shape？会带来哪些工程代价？

**回答：**
静态 Shape：编译阶段确定张量维度；优点：编译期可以做更多图优化、内存预分配，运行时没有 shape 推导开销，时延更稳定；缺点：一套 OM 只适配固定输入，输入变化就要重新编译。
动态 Shape：运行时确定张量；通用性强，一套模型支持多种输入；但是运行时 shape 推导带来额外开销，部分编译期优化无法生效，时延抖动更大。
华为基站业务输入尺寸固定，我选择静态 Shape 拿到更好时延；代价是模型通用性变差，输入改变就需要重新 ATC 编译。
像大模型推理，序列长度变化很大，就很难完全静态，要使用动态 shape 或者分档静态 shape。

### Q7：做混合精度量化的时候，经常出现性能提升但精度掉得比较多，你会从哪些维度定位精度退化来源？

**回答：**

1. 定位哪些层退化严重：逐层输出做余弦相似度、MSE 对比，定位敏感层；比如 Attention 的 Softmax、LayerNorm 对量化噪声通常更敏感；
2. 分析精度损失来源：截断溢出、舍入误差；Cast 转换次数过多；
3. 方案取舍：敏感层保留 FP16，非敏感层用 INT8；调整量化参数；或者微调校准数据集。
工程上不能一味追求低比特带来的速度，要绘制性能‑精度 Pareto 曲线，找到业务可接受的平衡点。

### Q8：开发自定义 Kernel 的时候，Tiling 分片你主要会考虑哪些硬件约束？

**回答：**

1. 片上 SRAM 大小：分片后输入输出中间数据总和不能超过片上存储，否则会发生溢出；
2. AI‑Core 硬件向量单元的对齐要求，分片大小尽量是硬件向量粒度的整数倍，避免低效 tail 计算；
3. 多核并行负载均衡：各个核分配的计算量尽量均等，防止部分核空闲；
4. DMA 搬运粒度：DMA 有最小传输粒度，分片要适配 DMA，避免小碎片传输带来带宽浪费。

## 项目与科研衍生开放题

### Q9：你在锂电池预测项目，把 LSTM 部署到静态编译 NPU，最大工程难点是什么？如果是大模型场景 RNN 类时序模型会遇到哪些新挑战？

**回答：**
当时最大难点：LSTM 隐状态 h0/c0 跨推理迭代的状态保存与传递，静态图编译不维护运行时状态。我的方案是把 h0/c0 显式作为模型输入输出，外部程序维护状态，配合滑动窗口。
放到大模型场景：序列很长，隐状态体量巨大；会带来显存压力；同时序列长度动态变化，静态编译约束很难适配，要结合动态 shape、KV‑Cache、分页内存等机制。

### Q10：你的 ReRAM 存内计算课题，用软件算法补偿硬件缺陷，那什么场景软件补偿性价比很低，必须改硬件？

**回答：**
软件补偿的代价是额外计算开销、推理时延上升。
当器件缺陷率非常高，软件需要巨大计算开销去纠错，带来性能、功耗开销已经超出业务容忍范围；或者故障模式过于复杂，算法很难建模，这种场景单纯软件就不划算，需要硬件增加修复、冗余单元。
软硬件协同不是软件万能，需要评估软件补偿带来的性能代价，判断边界。

## 职业迁移、学习与工程思维（阿里很爱问）

### Q11：你没有 CUDA/GPU 算子开发经验，如果入职之后交给你一个平头哥全新 AI 芯片，你会怎样快速上手开展优化工作？

**回答：**
我认为异构芯片底层优化方法论是相通的，Profiling‑瓶颈定位‑Kernel 开发‑精度性能验证这套闭环我已经跑通。上手新芯片我会分几步：

1. 吃透硬件手册：存储层次、AI 核能力、DMA 约束、编程模型；
2. 跑通基础 demo：官方样例，熟悉编译链、Profiling 工具，看懂性能指标；
3. 选择一个简单基准算子做练手，复现基线性能，尝试做 Tiling、融合优化，建立对硬件的体感；
4. 接着上真实业务算子，复现性能瓶颈，迭代优化；
5. 同时阅读开源加速库如 CUTLASS 学习通用算子优化思想。API 可以学，但瓶颈分析、权衡取舍是可迁移能力。

### Q12：一个算子理论上算下来算力很高，但实测硬件跑出来性能很差，可能有哪些原因？

**回答：**

1. 不是算力瓶颈，是访存瓶颈，数据搬运拖慢整体；
2. Tiling 分片不合理，片上溢出，频繁和全局内存交换数据；
3. 没有对齐硬件向量粒度，大量 tail 低效计算；
4. DMA 大量碎片化小传输，带宽没打满；
5. 算子调度开销大，大量小任务切换；
6. 算子中间张量频繁做类型转换，破坏融合。
理论 FLOPs 只是上限，真实性能更多受存储层次、调度约束限制。

### Q13：工程优化中，经常有多个优化手段，每个都有收益，但互相冲突，你一般怎么做方案选型？举一个你真实遇到的例子。

**回答：**
首先建立统一基线与评估指标，画出 Pareto 权衡曲线，不追求单项最优，追求业务约束下最优解。
举我实习的真实例子：引入 INT8 量化可以降低计算量，但是大量 Cast 算子打断算子融合，整体性能反而倒退。
我分别测试：全部 FP16、全部 INT8、部分层 INT8 混合方案，对比时延、精度，最后选择敏感层保留 FP16，非敏感层 INT8，换取融合收益，满足业务时延与精度双重约束。

### Q14：做软硬件系统优化，你觉得最容易踩的思维陷阱是什么？

**回答：**

1. 只看理论 FLOPs，忽略真实存储墙，纸上算得很好，实测跑不出来；
2. 只盯着时延，忽略精度退化，优化完速度上去但业务不可用；
3. 单一优化手段无限堆砌，不考虑副作用，比如盲目算子融合造成片上溢出；
4. 只用简单样例做验证，没有真实业务输入，在真实业务下优化收益消失。
所以每一项优化都必须：理论推演 + profiling 实测 + 业务输入下精度验证，形成闭环。
