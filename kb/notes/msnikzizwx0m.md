# 秋招项目与实习面试知识库

## 1. 使用目标

这套资料不是对原始文档的重复摘抄，而是把简历中的三项项目经历转换为面试可用的知识体系。每个项目都沿着以下主线组织：

> 业务问题 → 系统边界 → 总体架构 → 数据流 → 模块实现 → 技术选型 → 设计权衡 → 故障与改进 → 高频追问 → 证据边界

三个项目分别覆盖三类能力：

| 项目 | 面试能力标签 | 核心证明点 |
| --- | --- | --- |
| 昇腾锂电池寿命预测 | 端侧 AI 部署、时序模型、NPU 工具链 | 能把 PC 算法转换为边缘端推理工程 |
| ESP32 智慧蜂箱 | 嵌入式、FreeRTOS、外设、IoT、可靠性 | 能设计多任务固件并处理网络和资源约束 |
| ROS-Protobuf 分布式系统 | C++、Linux、ROS、序列化、gRPC | 能理解并扩展通信中间件，设计分布式监控原型 |

建议按四轮复习：

1. 第一轮：能不看资料画出项目架构和端到端数据流。
2. 第二轮：能解释每一项技术“为什么用、怎么实现、不用会怎样”。

4. 第四轮：严格核对真实性边界，不把文档设计、可编译原型或计划项描述成完成的实测结果。

## 3. 通用回答结构

### 3.1 项目介绍

使用六句话：

1. 场景和痛点；
2. 系统输入和输出；
3. 总体架构；
4. 自己负责的部分；
5. 最大技术难点；
6. 结果、验证方式和当前边界。

### 3.2 技术细节

不要只背定义，按以下顺序回答：

> 触发问题 → 约束条件 → 选择方案 → 代码/数据流实现 → 验证方式 → 代价和后续改进

### 3.3 不确定或缺少证据的问题

可使用以下口径：

> 这部分在当前版本中做到的是 A，B 是我设计的下一步方案，还没有完成规模化验证。当前能提供的证据是 C，因此我不会把 B 当成已经落地的结果。

这比猜测一个数字或把设计稿说成实测更可信。

## 4. 资料状态标记

文档中使用四级标记：

- `[源码确认]`：工作区存在对应实现，可指向具体代码。
- `[文档陈述]`：现有说明文档记录了该事实，但当前工作区没有对应源码或日志。
- `[原型]`：存在用于验证设计的代码，但没有完整集成或规模化验证。
- `[待补证]`：简历出现了量化结果或完成性表述，但原始材料不足以复核。

## 5. 当前版本的重要结论

- 昇腾项目的算法、转换和板端推理代码未收录在当前目录；知识库可讲清技术链路，但量化指标、五组电池明细和板端运行记录需要补证。
- 蜂箱项目有完整度较高的主控端和图传端固件；FreeRTOS、离线缓存、OTA、HTTP 图传可以落到代码解释。
- 分布式项目中，ROS-Protobuf 和本地 Qt 监控是已有子系统；gRPC 监控服务是原型。Qt 与 gRPC 尚未在代码层接通，Configure 也尚未真正下发到 Agent。
