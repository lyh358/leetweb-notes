# LeetCode 98 - 验证二叉搜索树（学习笔记）

## 一、题目信息

| 项目 | 内容 |
|------|------|
| 题号 | 98 |
| 难度 | 中等 |
| 标签 | 树、深度优先搜索、二叉搜索树、二叉树 |
| 核心思路 | 中序遍历 + 前驱节点比较 |

---

## 二、核心原理

> **BST 的中序遍历结果一定是严格递增的。**

这道解法就是利用这个性质：在"中序遍历"的过程中，检查每个节点的值是否严格大于上一个访问过的节点值。

---

## 三、完整代码

```cpp
class Solution {
public:
    long long prev = LLONG_MIN;

    bool isValidBST(TreeNode* root) {
        if(!root) return true;
        if(!isValidBST(root->left)) return false;

        if(root->val <= prev) return false;
        prev = root->val;

        if(!isValidBST(root->right)) return false;

        return true;
    }
};
```

---

## 四、逐行代码解析

### 4.1 成员变量初始化

```cpp
long long prev = LLONG_MIN;
```

定义一个**类成员变量** `prev`，用来记录中序遍历过程中**上一个被访问节点的值**。

- 初始化为 `long long` 的最小值，是为了防止树中存在 `INT_MIN` 这个节点值时误判。
- 用 `long long` 而不是 `int`，确保 `LLONG_MIN` 比任何合法的 `int` 节点值都小。

---

### 4.2 函数签名

```cpp
bool isValidBST(TreeNode* root) {
```

输入一个节点，返回以该节点为根的子树是否是一棵合法的 BST。

---

### 4.3 递归出口

```cpp
if(!root) return true;
```

空节点天然满足 BST 的性质，返回 `true`。

---

### 4.4 中序遍历第一步：递归验证左子树

```cpp
if(!isValidBST(root->left)) return false;
```

如果左子树本身就不是合法 BST，整棵树直接判定为非法，提前返回 `false`，不再往下执行。这就是**短路求值**的威力。

---

### 4.5 中序遍历第二步：处理当前节点（核心判断）

```cpp
if(root->val <= prev) return false;
```

此时左子树已经验证完毕，`prev` 中存的是中序遍历里当前节点的**前驱节点**的值。

- 如果当前节点值 `<= prev`，说明中序遍历序列**不是严格递增的**，违反了 BST 的性质，返回 `false`。

---

### 4.6 更新前驱指针

```cpp
prev = root->val;
```

当前节点验证通过后，把 `prev` 更新为当前节点的值，为下一个要访问的节点（中序遍历中的后继节点）做好准备。

---

### 4.7 中序遍历第三步：递归验证右子树

```cpp
if(!isValidBST(root->right)) return false;
```

同理，如果右子树不合法，直接返回 `false`。

---

### 4.8 返回结果

```cpp
return true;
```

左子树合法、当前节点值大于前驱、右子树合法——三个条件全部满足，当前子树是合法的 BST，返回 `true`。

---

## 五、用"黑盒思维"总结

| 概念 | 说明 |
|------|------|
| **黑盒承诺** | `isValidBST(root)` 会验证以 `root` 为根的子树是否是合法 BST，并在验证过程中**自动维护** `prev` 的值 |
| **当前层职责 ①** | 让黑盒去验证左子树（验证完后 `prev` 已经指向左子树中序遍历的最后一个节点，也就是当前节点的前驱） |
| **当前层职责 ②** | 检查当前节点值是否大于 `prev` |
| **当前层职责 ③** | 更新 `prev` 为当前节点值 |
| **当前层职责 ④** | 让黑盒去验证右子树 |

> 整个过程中，`prev` 就像一根**指针**，沿着中序遍历的顺序从左到右滑动，确保每一步都是严格递增的。

---

## 六、执行流程示例

以这棵树为例：

```
        5
       / \
      1    7
          / \
         6    8
```

中序遍历顺序：`1 → 5 → 6 → 7 → 8`

| 访问节点 | prev（访问前） | 判断 `val <= prev`? | prev（访问后） |
|---------|--------------|-------------------|--------------|
| 1       | LLONG_MIN    | 1 > LLONG_MIN ✓   | 1            |
| 5       | 1            | 5 > 1 ✓           | 5            |
| 6       | 5            | 6 > 5 ✓           | 6            |
| 7       | 6            | 7 > 6 ✓           | 7            |
| 8       | 7            | 8 > 7 ✓           | 8            |

结果：`true` ✅

## 八、易错点提醒

1. **为什么用 `long long`？** 节点值可能是 `INT_MIN`（即 `-2147483648`），如果用 `int` 类型的 `prev` 初始化为 `INT_MIN`，第一个节点值为 `INT_MIN` 时 `val <= prev` 会误判为 `false`。
2. **是 `<=` 不是 `<`**：BST 要求**严格递增**，相等也不行。
3. **为什么用成员变量而不是参数传递？** 成员变量天然在递归调用间共享状态，避免层层传参，代码更简洁。
