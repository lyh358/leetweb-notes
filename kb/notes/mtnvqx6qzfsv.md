## =={pink}大小端 32 位相关==

=={yellow}**(1) 判断大小端**==：=={green}**联合体 union，int 与 char 共用内存**，读取低字节判断==。

=={yellow}**(2) 大小端转换**==，颠倒 4 个字节顺序。

| 名称 | 别名 | 大小 |
| --- | --- | --- |
| bit | 位 (比特) | 1bit，0/1 |
| Byte | 字节 | 1 Byte = 8 bit |
| Word | 字 | 32 位机：4 字节；64 位机：8 字节 |

> 大小端操作的对象是**字节 (Byte)**，颠倒字节顺序，**不会改变字节内部每一个 bit（位）的顺序**。

比如 16 位数字 `0x1234`：
拆成 2 个**字节**：`0x12`、`0x34`
每个字节内部 8bit 不变，只是交换两个字节位置，得到`0x3412`。
字节里面的 bit 顺序不会翻转。

`0x01` 是**十六进制写法**。

- 1 个十六进制字符 = **4 bit**
- 两个十六进制字符 = **8 bit = 1 字节**

`0x01`：由两个十六进制符号：`0` 和 `1`

```ini
0x01  =  0000 0001  (二进制，一共8bit)
```

👉所以 `0x01` 是**1 字节，8 位**，不是 2bit。

### =={yellow}移位手动实现 32 位 uint 大小端互换（重点面试）==

把`0x12345678`，大小端翻转得到`0x78563412`

```cpp
//32位无符号整数大小端转换
uint32_t swap32(uint32_t num)
{
    uint32_t b1 = (num >> 24) & 0xFF;   //取最高字节
    uint32_t b2 = (num >> 16) & 0xFF;
    uint32_t b3 = (num >> 8)  & 0xFF;
    uint32_t b4 = num & 0xFF;          //取最低字节

    //重新拼接，颠倒字节顺序
    return (b4 << 24) | (b3 <<16) | (b2 <<8) | b1;
}
```

- `>>`右移取出各个字节；`&0xFF`保留一个字节，屏蔽高位；
- `<<`左移，把字节放到相反的字节位置；
- 按位或`|`把 4 个字节拼接成新数字。

## =={pink}C 语言结构体字节对齐，如何消除填充 (padding)字节==

CPU 默认会按照**自然对齐**给结构体插入填充字节，提升内存访问效率；但有时候做协议、二进制报文、寄存器映射时，我们**不要 padding**，需要**紧凑结构体**。

> ⚠️重要警告：
> 
> 
> 1. 取消对齐会产生**非对齐访问**，ARM、Xtensa (ESP32) 非对齐访问有的会崩溃、有的性能暴跌；只适合：网络协议、flash 存储、二进制序列化，**不要用来定义普通运行时变量**。
> 2. 不同编译器语法不一样：GCC (GCC/ESP‑IDF)、MSVC。

### GCC / ESP‑IDF / ARM‑GCC（最常用）

### =={yellow}方式 1：==`__attribute__((packed))` =={yellow}压缩属性==

```cpp
// 整个结构体取消填充，紧凑排列
typedef struct __attribute__((packed)) {
    uint8_t  a;   // 1字节
    uint32_t b;   // 4字节
    uint16_t c;   // 2字节
}my_pkt_t;
// 总大小 = 1+4+2 =7字节，没有padding
```

=={yellow}也可以写在结构体后面==：

```cpp
typedef struct {
    uint8_t  a;
    uint32_t b;
    uint16_t c;
} __attribute__((packed)) my_pkt_t;
```

> `__attribute__((packed))`=={yellow}：告诉编译器==**=={yellow}不要插入任何填充字节==**=={yellow}。==

### 风险点：非对齐访问！

### =={yellow}方式 2：修改对齐字节== `__attribute__((aligned(N)))`

`aligned(N)` 是设置**整个结构体的起始对齐要求**，不是消除 padding；
packed = 等价于 `aligned(1)`，按 1 字节对齐，不填充。

## =={pink}裸机 C 语言实现简易消息队列==

裸机：无操作系统，=={yellow}单主循环 + 中断==，消息队列用于**中断给主循环传递数据**，=={yellow}核心是环形缓冲区==。

=={yellow}核心：==**=={yellow}环形 FIFO 数组 + 头指针 head (写)、尾指针 tail (读)==**，=={yellow}裸机多用于**中断写、主循环读**==。

1. =={green}开辟一块**固定大小数组**作为**存储缓冲区**；**定义 head**（写入位置）、**tail**（读出位置）**两个变量**==。
2. **=={yellow}锁==**
3. 判断满：head 向后走一步等于 tail，则队列满。
4. 判断空：head 等于 tail，则队列空。
5. **入队（写）**：队列没满，把数据放到 head 指向位置，head 下标 + 1，超过数组长度就绕回 0。

> 如果中断和主循环都修改同一指针，访问 head/tail 前后加临界区（关中断）。

2. 使用约束：单生产者单消费者可以不用锁；多生产者 / 多消费者必须临界区保护共享指针；队列尽量短，不要存超大块数据。

## =={pink}互斥锁 (mutex) 底层原理（FreeRTOS 视角，面试口述版）==

互斥锁属于 RTOS **=={yellow}内核对象==**，专门=={yellow}用于保护多任务之间保护共享资源==；

=={pink}和**二值信号量  用途有本质区别**==。

## 🗣面试口述思路

> 互斥锁=={yellow}**本质**==是一个=={yellow}**内核结构体**==，
> 
> 
> **=={green}内部包含==**：
> 
> 
> **=={yellow}1.锁计数==**
> 
> 
> **=={yellow}2.持有该锁的任务句柄==**
> 
> 
> **=={yellow}3.优先级继承相关的成员==**

1. **=={yellow}核心机制：所有权==**
=={green}互斥锁有所有者概念==。=={green}任务调用==`xSemaphoreTake()`=={green}获取互斥锁==，=={green}获取成功之后，==**=={green}记录当前任务为锁的持有者==**；**=={yellow}只有==**=={green}**持有者任务才可以调用**==`xSemaphoreGive()`=={green}**释放锁**，别的任务不能替它释放==。=={pink}这是**和二值信号量最大区别**，**信号量没有所有者**，**任意任务都可以 give**。==
2. **=={yellow}计数递归锁==**
互斥锁**支持递归锁**（递归互斥锁）：=={green}**同一个任务**可以**多次 take**==，内部维护嵌套计数，=={green}**take 一次计数 + 1**，**give 一次计数‑1**；**计数减到 0** 才算**真正释放**锁。普通互斥锁不支持重复 take。==
3. **=={yellow}优先级继承（互斥锁特有，解决优先级反转）==**
=={green}当低优先级任务持有互斥锁，高优先级任务阻塞在这个锁上时==，内核会=={green}**临时把持有锁的低优先级任务的优先级提升到高优先级任务的优先级**===={green}。
防止中间优先级的任务抢占 CPU，以此缓解优先级反转；==锁释放之后，持有锁的任务恢复原来的优先级。
4. **=={yellow}底层依赖：ready list 阻塞链表==**
=={green}如果**任务** take 锁**拿不到锁**，任务就**进入阻塞态**==，=={green}**挂到**互斥锁对应的**等待事件链表**上==；=={green}**锁被释放**后，**内核唤醒**等待**链表上优先级最高**的任务。==
5. **=={yellow}互斥原理==**
互斥锁的内部访问操作（修改锁状态、等待链表），是=={green}**通过临界区（关中断 / 关闭调度器）保证原子性**==，防止多任务并发破坏锁的内部状态。

## 高频追问 1：互斥锁 vs 二值信号量区别

✅口述：=={green}互斥锁用于**保护共享资源**、二值信号量用于**事件通知**==

> 1. =={yellow}互斥锁有**任务所有权**==，=={green}只有持有者可以释放==；=={yellow}二值信号量没有所有者==，=={green}任意任务都可以 give。==
> 2. =={yellow}互斥锁**自带优先级继承**机制==，专门用来解决优先级反转，=={yellow}用于资源互斥保护==；=={yellow}二值信号量没有优先级继承，多用于事件通知。==
> 3. =={yellow}互斥锁**支持递归版本**==；=={green}二值信号量不支持递归==。

## 高频追问 2：优先级继承有什么缺点？

✅口述：

> =={yellow}**只能缓解，不能完全消除优先级反转**==；=={yellow}不能处理链式反转==；会改变任务原始优先级，内核实现复杂。

## 高频追问 3：中断里面能不能 take/give 互斥锁？

✅口述：

> **=={yellow}中断不允许操作互斥锁==**。互斥锁有任务所有权，绑定任务上下文，=={green}**中断没有任务句柄**，不能使用==。=={green}中断同步只能用**信号量、队列的**==`xxx_FromISR`=={green}**接口**。==

## =={pink}极简记忆卡片==

1. =={yellow}互斥锁 = 带==**=={yellow}所有权==** =={yellow}+**优先级继承**== =={yellow}的内核对象==；
2. =={yellow}拿==不到锁，任务**挂入阻塞链表**；内部操作靠**临界区保证原子**；
3. =={yellow}**只有持有者可以释放锁**；**中断不能操作 mutex**==；
4. =={yellow}和二值信号量不要混淆：**mutex** 用于**资源保护**；**二值信号量**多用于**事件通知**==。

> 补充：优先级天花板（优先级封顶）是另一种方案：创建互斥锁的时候直接给锁指定一个高优先级，拿到锁的任务直接抬升到该固定优先级。
