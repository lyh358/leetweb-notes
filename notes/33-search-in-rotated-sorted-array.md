# LeetCode 33. 搜索旋转排序数组 —— 二分查找变体学习笔记

> **题目**: [33. Search in Rotated Sorted Array](https://leetcode.cn/problems/search-in-rotated-sorted-array/)  
> **核心**: 整数数组 `nums` 按升序排列，但**在某个下标处进行了旋转**（如 `[0,1,2,4,5,6,7]` 旋转后可能变成 `[4,5,6,7,0,1,2]`）。给定目标值 `target`，如果 `target` 在数组中，返回其索引；否则返回 `-1`。  
> **要求**：时间复杂度必须是 $O(\log n)$。  
> **示例**:  
> ```
> nums = [4,5,6,7,0,1,2], target = 0  →  4
> nums = [4,5,6,7,0,1,2], target = 3  →  -1
> nums = [1], target = 0               →  -1
> ```

---

## 一、核心思想：旋转数组中必有一半有序

### 1.1 旋转数组的特性
原数组是升序的，经过一次旋转后，数组被分成两段有序的序列：

```
原数组: [0, 1, 2, 4, 5, 6, 7]
旋转点:     ↑ 在 4 前面切开，把 [4,5,6,7] 移到前面
旋转后: [4, 5, 6, 7, 0, 1, 2]
        └─────┘  └─────┘
         大段      小段
        有序递增  有序递增
```

关键性质：**旋转数组中不存在"局部下降"超过一次**。也就是说，数组中最多只有一个位置满足 `nums[i] > nums[i+1]`（即旋转点）。

### 1.2 为什么普通二分查找失效？
普通二分查找依赖于"中间元素将数组分成两个有序部分"的前提。但旋转后：

```
[4, 5, 6, 7, 0, 1, 2]
        ↑
       mid=3, nums[3]=7
```
`nums[mid]=7` 的左边 `[4,5,6,7]` 有序，右边 `[0,1,2]` 也有序，但**整体不是有序的**。我们无法直接判断 target 在 mid 的左边还是右边。

### 1.3 破局关键：至少有一半是有序的

虽然整体无序，但**以 mid 为界，左右两半中至少有一半是完全有序的**！

```
[4, 5, 6, 7, 0, 1, 2]
        ↑
       mid
左半: [4,5,6,7] → 有序（因为 nums[l]=4 <= nums[mid]=7）
右半: [0,1,2]   → 也有序

再看一个例子：
[6, 7, 0, 1, 2, 4, 5]
        ↑
       mid=3, nums[3]=1
左半: [6,7,0,1] → 无序（6 > 1，有旋转点）
右半: [2,4,5]   → 有序（因为 nums[mid]=1 < nums[r]=5）
```

**核心策略**：
1. 先判断哪一半是有序的；
2. 再看 target 是否落在有序的那一半范围内；
3. 如果在，就去那一半继续二分；
4. 如果不在，就去另一半。

## 二、代码实现（带完整注释）

```cpp
class Solution {
public:
    int search(vector<int>& nums, int target) {
        int n = nums.size();

        // ========== 边界情况处理 ==========
        if (n == 0) return -1;              // 空数组
        if (n == 1) return nums[0] == target ? 0 : -1;  // 单元素数组

        // ========== 二分查找主循环 ==========
        int l = 0, r = n - 1;               // 闭区间 [l, r]
        while (l <= r) {
            int mid = l + (r - l) / 2;      // 计算中点（防溢出）

            // 情况1：直接命中
            if (nums[mid] == target) {
                return mid;
            }

            // 情况2：左半部分 [l, mid] 是有序的
            // 判断依据：如果 nums[l] <= nums[mid]，说明从 l 到 mid 没有旋转点
            else if (nums[l] <= nums[mid]) {
                // 左半有序，检查 target 是否在左半的范围内
                // 注意：target 可以等于 nums[l]，但不能等于 nums[mid]（前面已判断不相等）
                if (nums[l] <= target && target < nums[mid]) {
                    // target 落在左半部分，去左边继续查找
                    r = mid - 1;
                } else {
                    // target 不在左半部分，去右边查找
                    l = mid + 1;
                }
            }

            // 情况3：右半部分 [mid, r] 是有序的
            // 判断依据：nums[l] > nums[mid]，说明旋转点在左半部分，因此右半部分一定有序
            else {
                // 右半有序，检查 target 是否在右半的范围内
                // 注意：target 可以等于 nums[r]，但不能等于 nums[mid]
                if (nums[mid] < target && target <= nums[r]) {
                    // target 落在右半部分，去右边继续查找
                    l = mid + 1;
                } else {
                    // target 不在右半部分，去左边查找
                    r = mid - 1;
                }
            }
        }

        // ========== 未找到 ==========
        return -1;
    }
};
```

## 四、关键机制深度解析

### 4.1 为什么 "至少有一半有序" 总是成立？

旋转数组的结构决定了这一点：

```
旋转数组的两种形态：

形态A：旋转点在右半部分
[4, 5, 6, 7, 0, 1, 2]
        ↑
       mid
左半: [4,5,6,7] → 有序（nums[l] <= nums[mid]）
右半: [0,1,2]   → 也有序

形态B：旋转点在左半部分
[6, 7, 0, 1, 2, 4, 5]
        ↑
       mid
左半: [6,7,0,1] → 无序（nums[l]=6 > nums[mid]=1）
右半: [2,4,5]   → 有序（nums[mid]=1 < nums[r]=5）
```

因为整个数组只旋转了一次，所以**旋转点要么在 mid 左边，要么在 mid 右边（或恰好在边界）**。无论哪种情况，mid 的一侧必然不跨越旋转点，因此那一侧是完全有序的。

### 4.2 范围判断的边界条件

```cpp
// 左半有序时
target >= nums[l] && target < nums[mid]
```
- `target >= nums[l]`：target 不小于左边界；
- `target < nums[mid]`：target 严格小于 mid（因为 `nums[mid] != target` 已在前面判断）。

```cpp
// 右半有序时
target > nums[mid] && target <= nums[r]
```
- `target > nums[mid]`：target 严格大于 mid（同理）；
- `target <= nums[r]`：target 不大于右边界。

**注意**：这里的 `<` 和 `>` 是严格的，因为 `nums[mid] == target` 的情况已经在前面 `if (nums[mid] == target)` 中处理了。

### 4.3 为什么 `nums[l] <= nums[mid]` 能判断左半有序？

如果左半部分 `[l, mid]` 跨越了旋转点，那么旋转点前后的元素会出现"断崖"下降，即 `nums[l] > nums[mid]`。

反之，如果 `nums[l] <= nums[mid]`，说明从 `l` 到 `mid` 是单调递增的，没有旋转点，因此左半部分完全有序。

```
反例验证：
[6, 7, 0, 1], l=0, mid=2
nums[l]=6, nums[mid]=0
6 > 0 → 左半无序 ✓（确实跨越了旋转点 0）

[4, 5, 6, 7], l=0, mid=2
nums[l]=4, nums[mid]=6
4 <= 6 → 左半有序 ✓
```

## 五、与 LeetCode 81（搜索旋转排序数组 II）的区别

| 对比项 | 本题 LeetCode 33 | LeetCode 81 |
|:------:|:----------------:|:-----------:|
| **数组元素** | 互不相同 | **可能重复** |
| `nums[l] <= nums[mid]` 判断 | 可靠 | 当 `nums[l] == nums[mid]` 时失效 |
| 最坏时间复杂度 | $O(\log n)$ | $O(n)$（需要缩边处理） |
| 核心难点 | 判断哪半有序 | 处理重复元素导致的歧义 |

**LeetCode 81 的关键问题**：
当 `nums[l] == nums[mid] == nums[r]` 时，无法判断哪半有序。例如 `[1, 0, 1, 1, 1]`，mid 指向 1，左右都有序但也都有重复，无法确定 target 在哪边。此时需要 `l++` 或 `r--` 缩边，最坏退化为线性。

## 七、易错点与面试 Tips

### ❌ 错误 1：范围判断时包含 `nums[mid]`
```cpp
// 错误！nums[mid] 已经确认不等于 target
if (nums[l] <= target && target <= nums[mid])  // ❌ 第二个 <= 是错的

// 正确
if (nums[l] <= target && target < nums[mid])   // ✅
```

### ❌ 错误 2：判断有序的条件写反
```cpp
// 错误
if (nums[l] > nums[mid])  // 这判断的是左半无序，不是有序

// 正确
if (nums[l] <= nums[mid])  // ✅ 判断左半有序
```

### ❌ 错误 3：忘记处理 `n == 0` 或 `n == 1`
```cpp
// 虽然二分循环也能处理 n=1，但显式处理更清晰，避免意外
if (n == 0) return -1;
if (n == 1) return nums[0] == target ? 0 : -1;
```

### ❌ 错误 4：右半有序时范围判断写错
```cpp
// 错误
if (target >= nums[mid] && target <= nums[r])  // ❌ 第一个 >= 是错的

// 正确
if (target > nums[mid] && target <= nums[r])   // ✅
```

### ❌ 错误 5：`mid` 计算溢出
```cpp
int mid = (l + r) / 2;  // 不推荐
int mid = l + (r - l) / 2;  // ✅
```

### ✅ 面试回答框架
1. **思路**：旋转数组中，以 mid 为界必有一半有序；先判断哪半有序，再看 target 是否在该半范围内；
2. **有序判断**：`nums[l] <= nums[mid]` 说明左半有序，否则右半有序；
3. **范围判断**：有序半的边界范围内包含 target，就去那一半；否则去另一半；
4. **复杂度**：时间 $O(\log n)$，空间 $O(1)$；
5. **扩展**：如果数组有重复元素（LeetCode 81），最坏会退化到 $O(n)$。

### ✅ 追问准备
- **问**：怎么找旋转点（最小元素）的下标？  
  **答**：同样用二分，判断哪半无序，旋转点就在哪半。`nums[mid] > nums[r]` 说明旋转点在右半，`nums[mid] < nums[r]` 说明旋转点在左半（或就是 mid）。

- **问**：如果不知道是否旋转过，代码还能用吗？  
  **答**：可以。如果数组本身就是有序的（无旋转），`nums[l] <= nums[mid]` 始终成立，算法退化为普通二分查找，依然正确。

## 八、一句话总结

> **旋转数组虽然整体无序，但切一刀下去总有一半是"干净"有序的。先找到这半有序区间，再看 target 在不在里面——在就钻进去继续二分，不在就去另一半。重复这个过程，$\log n$ 步内必出结果。**

| 要点 | 内容 |
|------|------|
| 核心策略 | 判断哪半有序 → 判断 target 是否在有序半 → 缩范围 |
| 左半有序判断 | `nums[l] <= nums[mid]` |
| 右半有序判断 | `nums[l] > nums[mid]`（即 else 分支） |
| target 在左半 | `nums[l] <= target < nums[mid]` |
| target 在右半 | `nums[mid] < target <= nums[r]` |
| 时间复杂度 | $O(\log n)$ |
| 空间复杂度 | $O(1)$ |
| 最大坑点 | 范围判断的边界要严格（不能包含 nums[mid]） |
