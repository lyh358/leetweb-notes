# 十一、数据结构与算法

# 一、数据结构

## 01 单链表和双链表区别

| 维度           | 单链表                                                | 双链表                                                  |
| :------------- | :---------------------------------------------------- | :------------------------------------------------------ |
| 节点结构       | 包含数据域 + 后继指针（next）                         | 包含数据域 + 后继指针（next） + 前驱指针（prev）        |
| 遍历方向       | 仅能从表头到表尾单向遍历                              | 可双向遍历（表头→表尾 / 表尾→表头）                     |
| 增删操作       | 删节点需先找到前驱节点（O (n)）；增节点需知道前驱位置 | 删节点可直接通过 prev 找前驱（O (1)）；增节点可双向定位 |
| 内存开销       | 小（仅一个指针）                                      | 大（两个指针，嵌入式中需权衡内存）                      |
| 嵌入式适用场景 | 数据单向访问、内存紧张场景（如简单设备链表）          | 需频繁双向遍历 / 增删（如 RTOS 中的任务控制块链表）     |

## 02 嵌入式中什么时候选数组、什么时候选链表？

**选数组的场景：**

- a．数据量固定且已知（如寄存器配置表、外设参数表）：数组内存连续，访问速度 O (1)，适配硬件地址映射（如 STM32 的 GPIO 寄存器组是连续地址，用数组直接索引）。
- b．对访问速度要求高（如实时数据采样缓存）：数组随机访问无指针跳转，耗时稳定，满足嵌入式实时性。
- c．内存碎片敏感场景：数组一次性分配连续内存，无碎片问题（嵌入式内存资源有限，碎片会导致后续分配失败）。

**选链表的场景：**

- a．数据量动态变化（如设备驱动的设备链表、RTOS 的消息队列节点）：链表增删无需移动其他元素，适配动态挂载 / 卸载设备的需求。
- b．内存无法分配连续大块空间（如系统运行后期内存碎片化）：链表节点可分散分配，充分利用零散内存。
- c．需频繁增删（如定时器链表）：链表增删操作仅修改指针，效率高于数组（数组增删需移动元素，O (n) 耗时）。

## 03 循环链表的应用场景？

嵌入式中循环链表的核心价值是 “首尾相连，无边界遍历”，典型场景：

1. **RTOS 任务调度链表**：就绪态任务用循环链表组织，调度器从当前任务节点开始遍历，遍历到链表尾自动回到表头，无需判断边界，提升调度效率。
2. **环形缓冲区（循环队列）底层**：基于循环链表实现串口 / DMA 数据缓存，读写指针循环移动，充分利用缓存空间（对比普通队列的 “假溢出” 问题）。
3. **外设轮询管理**：多个同类型外设（如多个传感器）用循环链表管理，轮询时从当前节点开始依次访问，避免重复遍历表头。
4. **容错系统的冗余节点管理**：如双机热备系统中，主备节点用循环链表维护，故障时直接切换到下一个节点，无需重新构建链表。

## 04 嵌入式中数组越界的危害

嵌入式中数组越界的影响远大于通用编程，核心危害：

1. **覆盖栈 / 堆数据**：栈空间（如函数局部变量、返回地址）通常很小（嵌入式栈大小一般 KB 级），数组越界会覆盖栈中的返回地址或函数参数，导致程序跳转到错误地址执行，直接崩溃 / 死机。
2. **改写硬件寄存器地址**：嵌入式中数组常映射到硬件地址（如 `uint32_t gpio_reg[] = (uint32_t*)0x40010800;`，对应 STM32 GPIOA 寄存器），越界会修改相邻寄存器（如 GPIOA 的 ODR 寄存器越界可能改写 GPIOA 的 BSRR 寄存器），引发硬件误动作（如错误输出电平、触发中断）。
3. **破坏系统关键数据**：越界可能覆盖内核 / RTOS 的关键结构（如任务控制块 TCB），导致系统调度异常、内存管理混乱。
4. **安全风险**：恶意数据触发数组越界可篡改程序逻辑，嵌入式设备（如工业控制器）被攻击后可能引发生产事故。

## 05 内核中内存底层使用什么数据结构实现

以 Linux 内核（嵌入式最常用内核）为例，不同内存管理模块的底层数据结构：

1. 伙伴系统（Buddy System）

   ：管理物理页框（4KB/8KB 等），用空闲块链表 + 二叉树实现：

   - 按块大小（2^n 个页框）维护多个空闲链表（如 1 页、2 页、4 页链表）；
   - 二叉树用于快速合并相邻空闲块（“伙伴” 块），解决内存碎片问题。

2. Slab 分配器

   ：管理内核小对象（如 task_struct、file 结构体），用链表 + 着色页实现：

   - 每个缓存（如 task 缓存）包含多个 slab（由连续页组成），slab 内用链表管理空闲对象；
   - 着色页避免 CPU 缓存冲突，提升访问效率。

3. 虚拟内存区域（VMA）

   ：管理进程虚拟地址空间，用链表 + 红黑树实现：

   - 链表遍历所有 VMA（如 mmap 映射区、栈区），红黑树用于快速查找指定地址所属的 VMA（O (logn) 效率）。

4. **内存池（MemPool）**：嵌入式内核常用的定长内存池，用单向链表管理空闲块：链表节点直接嵌入内存块中，分配 / 释放仅修改指针，无内存碎片且实时性高。

## 06 哈希冲突如何解决

哈希冲突是指不同关键字映射到同一哈希地址，核心解决方法及嵌入式适用性：

1. **开放定址法**
   - 原理：冲突时按一定规则（线性探测、二次探测、伪随机探测）寻找下一个空闲地址。
   - 嵌入式适配性：内存开销小（无需额外指针），但易出现 “堆积”（连续地址被占用），实时性不确定（探测次数不固定），适用于小数据量场景（如简单设备 ID 映射）。
2. **链地址法（拉链法）**
   - 原理：每个哈希地址对应一个链表，冲突元素插入链表尾部。
   - 嵌入式适配性：处理冲突效率高，无堆积，但需额外存储链表指针（内存开销大），嵌入式中仅用于数据量小、内存充足的场景（如内核中的文件描述符哈希表）。
3. **再哈希法**
   - 原理：冲突时用另一个哈希函数计算新地址，直到找到空闲地址。
   - 嵌入式适配性：无堆积，但多次哈希计算耗时，实时性差，极少使用。
4. **建立公共溢出区**
   - 原理：单独开辟一块内存作为溢出区，冲突元素全部放入溢出区，用顺序查找访问。
   - 嵌入式适配性：实现简单，适合冲突率极低的场景（如硬件 ID 哈希表）。

## 07 哈希搜索底层如何实现

| 组件     | 作用                                                         |
| :------- | :----------------------------------------------------------- |
| 哈希函数 | 将任意长度的键（如字符串、整数）映射为固定范围的整数（哈希表下标） |
| 哈希表   | 存储数据的数组（核心载体），下标由哈希函数计算得出           |
| 冲突解决 | 处理 “不同键映射到同一下标” 的问题（哈希冲突）               |

# 二、算法

## 01 排序算法

嵌入式排序算法选型核心：内存开销小、实时性稳定、适配硬件资源，常用算法及场景：

| 算法     | 时间复杂度 | 内存开销           | 嵌入式适用场景                     | 优化要点                                   |
| :------- | :--------- | :----------------- | :--------------------------------- | :----------------------------------------- |
| 冒泡排序 | O(n²)      | O(1)               | 小数据量（n<100）、内存极度紧张    | 加标志位，无交换时提前终止                 |
| 插入排序 | O(n²)      | O(1)               | 数据基本有序（如传感器采样数据）   | 折半查找插入位置，减少比较次数             |
| 快速排序 | O(nlogn)   | O (logn)（递归栈） | 大数据量（n>100）、允许递归        | 非递归实现（避免栈溢出），选中位数作为基准 |
| 堆排序   | O(nlogn)   | O(1)               | 实时性要求高（耗时稳定）、大数据量 | 原地建堆，非递归实现                       |
| 归并排序 | O(nlogn)   | O(n)               | 极少使用（额外内存开销大）         | 无（嵌入式中）                             |

## 02 位掩码的作用

位掩码是用二进制位表示状态 / 配置的技术，嵌入式中是操作硬件寄存器的核心手段，作用：

1. 寄存器精准操作：
   - 置 1 特定位：`GPIOA->BSRR = 1 << 5;`（用掩码 `1<<5` 置位 GPIOA 的 Pin5，不影响其他位）。
   - 清 0 特定位：`GPIOA->BRR = 1 << 5;`（用掩码 `1<<5` 清零 Pin5）。
   - 读取特定位：`uint8_t pin_state = (GPIOA->IDR >> 5) & 1;`（用掩码 `1` 提取 Pin5 状态）。
2. **中断管理**：用掩码屏蔽 / 使能特定中断，如 `NVIC->ISER[0] = 1 << 6;`（使能 EXTI0 中断，掩码 `1<<6` 对应中断号）。
3. **状态标志位压缩存储**：用 1 个字节存储 8 个布尔状态（如传感器在线 / 离线、报警触发 / 未触发），节省内存（嵌入式中内存以字节为单位，BOOL 类型占 1 字节，位掩码可 8 倍压缩）。
4. **硬件功能配置**：如 SPI 控制器的 CR1 寄存器，用不同位掩码配置波特率（`0b011` 对应 fPCLK/16）、主从模式（`0b1` 为主模式）等，无需修改整个寄存器。

## 03 CRC16/CRC32 校验的实现思路

CRC（循环冗余校验）是嵌入式通信 / 存储中最常用的差错校验算法，核心实现思路（以 CRC16‑CCITT 为例）：

1. **原理基础**：基于模 2 除法（无进位加法 / 减法，等价于异或），将数据视为二进制多项式，除以预设的生成多项式（如 CRC16 的生成多项式 \(G(x)=x^{16}+x^{12}+x^5+1\)，对应二进制 `0x1021`），余数即为 CRC 值。

2. 分步实现

   ：

   - 初始化：CRC 寄存器赋值初始值（如 CRC16‑CCITT 初始值为 `0xFFFF`）。
   - 逐字节处理数据：
     - i . 将当前数据字节与 CRC 寄存器的高 8 位异或，结果存入 CRC 寄存器高 8 位。
     - ii . CRC 寄存器左移 1 位，若移到位为 1，则与生成多项式 `0x1021` 异或；若为 0，直接左移。
     - iii . 重复步骤 2，直到当前字节的 8 位全部处理完毕。
   - 结果输出：所有数据处理完成后，CRC 寄存器的值即为最终 CRC 校验码（可选择反转、异或最终值等优化）。

3. 嵌入式优化

   ：

   - 查表法：预计算 256 个字节对应的 CRC 值（字节表），处理数据时直接查表代替逐位计算，将时间复杂度从 O (8n) 降至 O (n)，提升实时性（嵌入式通信中优先使用查表法）。
   - 硬件加速：部分 MCU（如 STM32）内置 CRC 硬件模块，直接写入数据即可自动生成 CRC 值，减少 CPU 开销。

4. **应用场景**：串口通信数据帧校验、CAN 总线数据校验、Flash 存储数据完整性校验、SD 卡数据传输校验。

## 04 反转某一个位 & 异或 如何写

**核心原理**

位反转（指定位取反）的核心是利用异或（`^`）运算的特性：

- 一个位与 **1** 异或 → 反转（0→1，1→0）；
- 一个位与 **0** 异或 → 保持不变。

因此，要反转第 n 位（位编号从 0 开始，最低位为第 0 位），只需构造一个 “仅第 n 位为 1，其余位为 0” 的掩码，再与原数异或即可。

**步骤与代码实现（C 语言）**

```
#include <stdio.h>

// 反转val的第n位（n从0开始，如第0位=最低位）
unsigned int reverse_bit(unsigned int val, int n) {
    // 构造掩码：1左移n位，得到仅第n位为1的数
    unsigned int mask = 1 << n;
    // 异或反转指定位
    return val ^ mask;
}

int main() {
    unsigned int num = 0b1010; // 十进制10，二进制1010
    int bit_pos = 1;           // 要反转第1位（原数第1位是0）

    unsigned int res = reverse_bit(num, bit_pos);
    printf("原数: %u (%0b)\n", num, num);        // 输出: 10 (0b1010)
    printf("反转第%d位后: %u (%0b)\n", bit_pos, res, res); // 输出: 12 (0b1100)
    return 0;
}
```

## 05 如何使用位运算实现取余计算

**核心原理**

位运算实现取余仅适用于除数为 **2 的幂次**（如 2、4、8、16...），核心利用二进制的特性：

- 对于除数 \(div = 2^k\)（k 为正整数），数值 x 对 div 取余的结果 = `x & (div - 1)`；
- 原理：二进制中，\(2^k\) 是 1 后面跟 k 个 0，\(2^k‑1\) 是 k 个 1，与 x 按位与后，结果为 x 的最后 k 位（即余数）。

**示例推导**

比如 x=15，div=8（\(2^3\)）：

- `div‑1=7（0b0111）`；
- `15 & 7 = 15(0b1111) & 0b0111 = 0b0111 = 7`，而 `15 % 8 = 7`，结果一致。

**代码实现（C 语言）**

```
#include <stdio.h>

// 位运算实现取余（仅适用于div=2^k）
unsigned int mod_by_bit(unsigned int x, unsigned int div) {
    // 校验：div必须是2的幂次（二进制仅1个1）
    if (((div & (div - 1)) != 0)) {
        printf("错误：除数必须是2的幂次！\n");
        return -1;
    }
    return x & (div - 1);
}

int main() {
    unsigned int x = 25;
    unsigned int div1 = 4;  // 2^2，合法
    unsigned int div2 = 5;  // 非2的幂次，非法
}
    unsigned int div2 = 5;  // 非2的幂次，非法

    printf("25 %% 4 = %u (位运算结果: %u)\n", 25%4, mod_by_bit(25, div1));  // 输出: 1 1
    mod_by_bit(25, div2);  // 输出错误提示
    return 0;
 }
```
