# 力扣 75. 颜色分类 — 学习笔记（双指针覆盖法）

## 一、题目概述

给定一个包含红色、白色和蓝色（分别用数字 `0`、`1`、`2` 表示）的数组 `nums`，**原地**对它们进行排序，使得相同颜色的元素相邻，并按照红色、白色、蓝色顺序排列。

> **关键约束**：数组中只有 `0`、`1`、`2` 三种值，且要求 **原地排序**（不能使用额外数组）。

---

## 二、双指针覆盖法

### 核心思想

这个解法的精髓在于**"覆盖写入"**而非"交换"：

- 遍历数组时，先把当前位置**默认覆盖为 2**（相当于把当前元素"移走"）
- 如果原元素是 `0` 或 `1`，则在 `p1` 位置**写入 1**，`p1` 右移
- 如果原元素是 `0`，还要在 `p0` 位置**写入 0**，`p0` 右移

由于 `p0 <= p1`，当在 `p0` 处写 `0` 时，如果 `p0 < p1`，这个位置之前可能已经被写过 `1` 了，现在被 `0` 覆盖。但因为 `p1` 已经右移，之前写的 `1` 已经被"保存"在了数组更后面的位置。

### 代码分析

```cpp
class Solution {
public:
    void sortColors(vector<int>& nums) {
        int p0 = 0, p1 = 0;           // p0: 0 的右边界；p1: 1 的右边界
        for (int i = 0; i < nums.size(); i++) {
            int x = nums[i];

            // 先把当前位置覆盖为 2（相当于把当前元素"腾空"）
            nums[i] = 2;

            // 如果原元素是 0 或 1，需要在 p1 处补一个 1
            if (x <= 1) {
                nums[p1++] = 1;
            }

            // 如果原元素是 0，还需要在 p0 处补一个 0
            // 注意：当 p0 < p1 时，这里会把之前写入的 1 覆盖为 0
            // 但那个 1 已经被 p1 的递增"保存"到了更后面的位置
            if (x == 0) {
                nums[p0++] = 0;
            }
        }
    }
};
```

### 复杂度分析

| 指标 | 复杂度 | 说明 |
|------|--------|------|
| **时间复杂度** | $O(n)$ | 单次线性遍历 |
| **空间复杂度** | $O(1)$ | 仅使用两个指针变量，原地操作 |
| **是否修改原数组** | ✅ 是 | 覆盖写入，原地完成 |

## 三、流程图解（示例）

数组：`[2, 0, 2, 1, 1, 0]`

| i | x | 操作 | 数组变化 | p0 | p1 | 说明 |
|---|---|------|---------|----|----|------|
| 0 | 2 | `nums[0]=2` | `[2, 0, 2, 1, 1, 0]` | 0 | 0 | 是 2，只覆盖 |
| 1 | 0 | `nums[1]=2` → `nums[0]=1` → `nums[0]=0` | `[0, 2, 2, 1, 1, 0]` | 1 | 1 | 先写 1，再写 0 覆盖 |
| 2 | 2 | `nums[2]=2` | `[0, 2, 2, 1, 1, 0]` | 1 | 1 | 是 2，只覆盖 |
| 3 | 1 | `nums[3]=2` → `nums[1]=1` | `[0, 1, 2, 2, 1, 0]` | 1 | 2 | 写 1，p1 前进 |
| 4 | 1 | `nums[4]=2` → `nums[2]=1` | `[0, 1, 1, 2, 2, 0]` | 1 | 3 | 写 1，p1 前进 |
| 5 | 0 | `nums[5]=2` → `nums[3]=1` → `nums[1]=0` | `[0, 0, 1, 1, 2, 2]` | 2 | 4 | 先写 1，再写 0 覆盖 |

最终结果：`[0, 0, 1, 1, 2, 2]` ✅

> **关键观察**：第 5 步在 `p0=1` 处写 `0` 时，把之前第 3 步写入的 `1` 覆盖了。但那个 `1` 已经被 `p1` 的递增记录了下来，并在后续步骤中被补到了 `p1-1=3` 的位置。

## 四、核心要点总结

### 1. p0 / p1 的本质含义

- **`p0`**：下一个 **`0`** 应该放入的位置
- **`p1`**：下一个 **`1`** 应该放入的位置

并且始终满足 **`p0 ≤ p1`**，这保证了数组被划分为四个明确的区间：

```
[0, 0, 0] [1, 1, 1] [2, 2, 2] [?, ?, ?]
  ↑p0       ↑p1       ↑i        待扫描
```

| 区间 | 范围 | 内容 |
|------|------|------|
| 0 区 | `[0, p0)` | 全是 `0` |
| 1 区 | `[p0, p1)` | 全是 `1` |
| 2 区 | `[p1, i)` | 全是 `2`（已处理部分） |
| 未知区 | `[i, n)` | 待扫描的元素 |

所以当你遇到 `0` 时：
1. 先在 `p1` 处放一个 `1`（把 1 区向右扩展）
2. 再在 `p0` 处放一个 `0`（把 0 区向右扩展）

如果此时 `p0 < p1`，第二步会覆盖掉刚才在 `p1` 处写的 `1`，但那个 `1` 已经被 `p1++` 记录，并在后续步骤中被保存到了更后面的位置。

> 本质上就是**一边遍历，一边把三个颜色的边界向右推进**。

---

### 2. 为什么 `p0` 的写入不会丢失 `1`？


因为 `p0 <= p1` 恒成立：
- 遇到 `1` 时，只有 `p1++`
- 遇到 `0` 时，`p1++` 且 `p0++`
- 所以 `p1` 永远 >= `p0`

当在 `p0` 处写 `0` 时，如果 `p0 == p1`，说明当前没有 `1` 需要保护；如果 `p0 < p1`，说明 `p1` 已经先一步把 `1"保存"到了数组更靠后的位置，此时覆盖是安全的。

### 2. 与经典荷兰国旗三指针法的对比

| 维度 | 双指针覆盖法 | 荷兰国旗三指针法 |
|------|-------------|-----------------|
| **指针数量** | 2 个（p0, p1） | 3 个（left, cur, right） |
| **核心操作** | 覆盖写入 | 交换元素 |
| **遍历方向** | 单向（从左到右） | 双向（cur 从左，right 从右） |
| **代码简洁度** | 更简洁，逻辑清晰 | 稍复杂，需处理交换后元素 |
| **时间复杂度** | $O(n)$ | $O(n)$ |
| **空间复杂度** | $O(1)$ | $O(1)$ |

### 3. 这个解法的优雅之处

- **不依赖交换**：直接覆盖，避免了交换带来的额外判断
- **单向遍历**：只需要从左到右走一遍，不需要回头
- **逻辑分层**：先处理"是不是 2"，再处理"是不是 1"，最后处理"是不是 0"，层层递进

## 五、扩展思考

### 如果颜色变成 4 种（0, 1, 2, 3）？

这个双指针覆盖法的思路可以扩展：
- 维护 `p0, p1, p2` 三个指针
- 遍历时先覆盖为 3
- 根据原值依次写入 2、1、0

但代码会变得繁琐，此时**荷兰国旗三指针法**的通用性更强（只需增加判断分支即可）。

### 为什么不能用计数排序后直接填充？

```cpp
// 计数排序思路（不符合"原地"精神）
int count[3] = {0};
for (int num : nums) count[num]++;
// 再按 count 填充数组...
```

虽然也是 $O(n)$ 时间、$O(1)$ 空间，但题目要求的是**一次遍历内完成原地调整**，计数排序需要两次遍历，且没有体现"分类"的算法美感。

---

## 六、关键收获

1. **覆盖写入是一种强大的原地操作技巧**。当确定后续会重新赋值时，可以先"大胆覆盖"。
2. **指针的相对位置关系**（`p0 <= p1`）是正确性的核心保证。
3. **针对有限取值范围的问题**，往往可以设计出比通用排序更优、更优雅的专用算法。
4. 这个解法展示了如何用**增量构建**的思想解决问题：遍历过程中逐步把 0、1、2 放到正确的区域，而不是先统计再整理。
