# 昇腾锂电池寿命预测：面试问答与追问链

## 1. 90 秒项目介绍

我做的是一个面向 BMS 健康管理的锂电池容量和剩余寿命预测系统。算法侧基于 NASA 循环数据提取 11 维退化特征，先用 GRA 过滤弱相关特征，再用 PCA 去除冗余并压缩为 4 维健康因子，最后用长度 21 的滑动窗口输入 LSTM，预测后续容量并根据 EOL 阈值换算剩余循环数。工程侧我把 PyTorch 权重按 `.pth→ONNX→OM` 转换，针对 Ascend 310B4 的静态编译约束固定输入为 `1×21×4`，并把 LSTM 的 `h0/c0` 设计为显式输入。板端通过 ACL Lite 完成运行时初始化、模型加载、推理、结果保存和资源释放。这个项目的重点不是只训练一个模型，而是理解时序模型从动态图到 NPU 静态图的接口、精度和运行时适配。当前备份中缺少原始训练和板端日志，因此量化指标需要用论文和结果表进一步补证。

## 2. 高频问题

### Q1：为什么 GRA 和 PCA 都要用？

GRA 根据目标容量筛掉弱相关特征，PCA 在保留的特征内部消除共线性并压缩维度。前者解决目标相关性，后者解决输入冗余，作用不重复。两者都必须只在训练集拟合，避免把测试序列信息泄漏到模型。

追问：PCA 会不会损失可解释性？

会。主成分是原始特征的线性组合，可解释性弱于原始物理量。可以保留载荷矩阵解释每个主成分，或用稀疏 PCA、基于物理先验的特征选择作为替代。

### Q2：为什么 LSTM 比 RNN 合适？

电池退化具有长期依赖，普通 RNN 反向传播要连续乘雅可比矩阵，容易梯度衰减或爆炸。LSTM 通过 cell state 和门控控制信息保留，使梯度和长期状态更容易传播。但 LSTM 更重、静态部署更复杂，所以也应与 GRU、TCN 做端侧对照。

### Q3：ONNX 在链路中是什么角色？

它是框架无关的计算图中间表示，把 PyTorch 的网络结构、权重和算子语义交给昇腾编译器。它不是最终运行时；ATC 还要把 ONNX 编译成与 Ascend310B4 匹配的 OM。

### Q4：为什么固定 Shape？

固定 Shape 让编译器提前知道每个张量大小和执行路径，从而规划内存、选择算子并优化图。代价是窗口和 batch 不灵活。项目训练本来就是长度 21 的单样本窗口，因此固定为 `1×21×4`。

### Q5：为什么显式输入 h0/c0？

静态 OM 每次调用是显式输入到显式输出，不会自动保留 Python 对象里的 RNN 状态。把 `h0/c0` 暴露为输入、`hn/cn` 暴露为输出，运行时才有机会管理跨调用状态。不过相邻滑窗高度重叠，是否跨窗传状态要通过真实脚本和消融实验确认，不能简单认为一定更好。

### Q6：为什么选择 opset 12？

它是当时 PyTorch 导出与 CANN/ATC 支持之间较稳定的兼容点。opset 不是 ONNX 文件版本号，而是算子语义集合版本；版本过新可能 ATC 不支持，过旧可能缺少合适的 LSTM 表达。

### Q7：为什么强制 FP32？

容量回归和 EOL crossing 对小数值偏差敏感，所以初版采用保守 FP32。严谨决策需要比较 FP16 的 RMSE、EOL 误差和时延；如果误差可接受，FP16 可以减少带宽和提高吞吐。

### Q8：如何验证迁移前后正确？

应分三级：PyTorch 与 ONNX Runtime 同输入比对；ONNX/OM 编译后在板端比对单样本输出；最后对完整测试集比较 RMSE、MAE、R²、EOL 误差和误差分布。同时确认预处理、PCA矩阵、特征顺序和反归一化完全一致。

### Q9：五组电池如何划分训练和测试？

当前材料无法确认。面试前必须从论文补齐。如果是同一电池前段训练、后段测试，衡量的是时间外推；如果留一电池测试，衡量的是跨电池泛化。二者难度不同，不能混说。

### Q10：准确率 99.8% 是什么？

当前没有公式，不能把它当通用回归准确率。建议回答 RMSE 和 EOL 误差，并说明“准确率”必须按论文的自定义定义解释；若无法找回公式，从简历删除该指标。

### Q11：模型在板端慢，怎么定位？

先拆成数据预处理、H2D、模型执行、D2H、后处理分别计时；再用 CANN Profiling 看算子、数据搬运和调度。小 LSTM 可能不是纯计算瓶颈，Python 调用、频繁小拷贝和同步也会占比高。可尝试预分配 buffer、批处理、减少 Host/Device 往返、FP16 和模型结构轻量化。

### Q12：如果 LSTM 算子 ATC 不支持怎么办？

先确认 CANN/opset/输入约束；再尝试固定序列、替换不支持属性，或把 LSTM 展开为 MatMul/Add/Sigmoid/Tanh 等基础算子。仍不合适时评估 GRU、TCN、1D CNN 等更易静态部署的模型。

## 3. 压力追问

### “你只是调工具，没有技术含量吧？”

工具调用只是表面，核心是保持训练和部署语义一致：网络结构与权重匹配、静态张量接口、LSTM 状态显式化、预处理参数一致、精度模式和 SoC 匹配、运行时资源生命周期，以及跨后端数值验证。任何一个环节错误都可能“能运行但结果错”。

### “为什么不直接在云端推理？”

云端易维护且算力强，但 BMS 场景存在时延、弱网、数据隐私和离线可用性需求。边缘端适合实时推理，云端适合集中训练和模型管理，二者可以协同。

### “你的结果是否可信？”

当前工作区只保留说明文档，没有足够原始产物复核最终简历数字。我可以完整解释方法和部署链路，但会把指标视为待补证，并从论文、脚本、每组结果表和板端日志恢复证据后再使用。这是当前最诚实的回答。
