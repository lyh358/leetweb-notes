# 🌲 回溯算法核心概念笔记 —— 剪枝 vs 终止条件

> 系统梳理回溯算法中两个最容易混淆的概念

---

## 📌 一、概念定义

### 1.1 终止条件（Termination Condition）

> **什么时候停止递归，把当前路径加入答案？**

终止条件是回溯算法的**成功出口**。当当前路径已经满足题目要求时，就把它记录下来，然后返回。

**类比**：走迷宫时，**找到宝藏了**，停下来标记位置，然后原路返回探索其他路径。

### 1.2 剪枝条件（Pruning Condition）

> **什么时候这条路已经走不通了，直接放弃，不再继续？**

剪枝条件是回溯算法的**失败出口**。当当前路径已经不可能满足题目要求时，直接返回，不再往下递归。

**类比**：走迷宫时，**前面是一堵墙**，没必要继续走，直接掉头。

### 1.3 一句话区分

| | 终止条件 | 剪枝条件 |
|---|---------|---------|
| **时机** | 递归到最深层，成功找到解 | 递归到某一层，发现此路不通 |
| **结果** | ✅ 收集当前路径到答案 | ❌ 直接返回，不收集 |
| **目的** | 记录合法解 | 减少无效搜索，提高效率 |
| **是否必须** | **必须有**（否则找不到答案） | **不必须**（但必须有才高效） |
| **形象比喻** | 到达终点，打卡拍照 | 看到死胡同，提前掉头 |

## 📋 二、逐题对比：终止条件 vs 剪枝条件

### 2.1 力扣 78. 子集

```cpp
// 终止条件：所有元素都处理完毕
if (idx == nums.size()) {
    ans.push_back(path);   // ✅ 每个叶子节点都是子集
    return;
}

// 剪枝条件：无（子集问题天然不需要剪枝）
// 因为每个元素只有选/不选两种状态，一定会遍历完
```

| 类型 | 条件 | 说明 |
|-----|------|------|
| **终止条件** | `idx == nums.size()` | 所有元素处理完，当前 path 是一个完整子集 |
| **剪枝条件** | 无 | 子集问题没有无效路径，所有分支都合法 |

---

### 2.2 力扣 77. 组合

```cpp
// 终止条件：已经选了 k 个数
if (path.size() == k) {
    ans.push_back(path);   // ✅ 选够了，记录
    return;
}

// 剪枝条件：剩下的数不够凑齐 k 个
for (int i = start; i <= n - (k - path.size()) + 1; i++) {
    // 如果 i 超过这个范围，后面就算全选也凑不够 k 个
}
```

| 类型 | 条件 | 说明 |
|-----|------|------|
| **终止条件** | `path.size() == k` | 选够了 k 个数，记录组合 |
| **剪枝条件** | `i <= n - (k - path.size()) + 1` | 剩余数字不够凑齐 k 个，提前终止循环 |

**剪枝效果**：比如 `n=20, k=2`，当 `path.size()=1` 时，`i <= 20 - 1 + 1 = 20`，但如果 `path.size()` 已经很大，很多分支会被剪掉。

---

### 2.3 力扣 46. 全排列（交换法）

```cpp
// 终止条件：所有位置都固定好了
if (start == nums.size()) {
    ans.push_back(nums);   // ✅ 得到一个完整排列
    return;
}

// 剪枝条件：无（交换法天然不需要剪枝）
// 因为每次交换都是合法操作，不会产生无效分支
```

| 类型 | 条件 | 说明 |
|-----|------|------|
| **终止条件** | `start == nums.size()` | 所有位置都确定了，得到一个排列 |
| **剪枝条件** | 无 | 交换法通过位置固定保证合法性，无需剪枝 |

---

### 2.4 力扣 39. 组合总和（for 循环版）

```cpp
// 终止条件：和恰好等于 target
if (sum == target) {
    ans.push_back(path);   // ✅ 找到一个合法组合
    return;
}

// 剪枝条件：和已经超过 target
if (sum > target) return;   // ❌ 超了，这条路废了

// 或者排序后在循环内剪枝：
if (sum + candidates[i] > target) break;
```

| 类型 | 条件 | 说明 |
|-----|------|------|
| **终止条件** | `sum == target` | 和恰好等于目标值，记录组合 |
| **剪枝条件** | `sum > target` 或 `sum + candidates[i] > target` | 和已经超过目标，再往下加只会更大 |

**剪枝效果**：如果不剪枝，会递归很多 `sum > target` 的无用分支，导致超时。

---

### 2.5 力扣 39. 组合总和（选/不选版）

```cpp
// 终止条件 1：指针越界（失败）
if (idx == candidates.size()) return;   // ❌ 没凑够，直接返回

// 终止条件 2：target 减到 0（成功）
if (target == 0) {
    ans.push_back(path);   // ✅ 找到合法组合
    return;
}

// 剪枝条件：选了当前数会超过 target
if (target - candidates[idx] >= 0) {
    // 只有不超才能选
}
```

| 类型 | 条件 | 说明 |
|-----|------|------|
| **终止条件（成功）** | `target == 0` | 剩余目标值为 0，说明凑够了 |
| **终止条件（失败）** | `idx == candidates.size()` | 所有数都考虑完了还没凑够 |
| **剪枝条件** | `target - candidates[idx] < 0` | 选了会超，不进入「选」分支 |

> 💡 **注意**：这道题有两个终止条件！一个成功，一个失败。

---

### 2.6 力扣 17. 电话号码的字母组合

```cpp
// 终止条件：所有数字都处理完了
if (idx == digits.size()) {
    ans.push_back(path);   // ✅ 得到一个完整字母组合
    return;
}

// 剪枝条件：无（每层候选集独立，没有无效分支）
```

| 类型 | 条件 | 说明 |
|-----|------|------|
| **终止条件** | `idx == digits.size()` | 所有数字都翻译完了 |
| **剪枝条件** | 无 | 每个数字对应的字母都要遍历，没有无效路径 |

---

### 2.7 力扣 22. 括号生成

```cpp
// 终止条件：左右括号都用完了
if (left == 0 && right == 0) {
    ans.push_back(str);   // ✅ 得到一个合法括号串
    return;
}

// 剪枝条件：剩余左括号比右括号多
if (left > right) return;   // ❌ 说明右括号用多了，一定非法
```

| 类型 | 条件 | 说明 |
|-----|------|------|
| **终止条件** | `left == 0 && right == 0` | 所有括号都放完了，字符串合法 |
| **剪枝条件** | `left > right` | 已放 `')'` 比 `'('` 多，任何后续都无法挽救 |

**剪枝效果**：根节点直接放 `')'` 就会被剪枝，因为 `left=3 > right=2`。

## 🧠 四、如何判断是否需要剪枝？

### 4.1 必须剪枝的情况

| 场景 | 剪枝方式 | 代表题目 |
|-----|---------|---------|
| **和/积超过目标值** | 超过就返回 | 39. 组合总和 |
| **剩余元素不够凑齐** | 循环上限控制 | 77. 组合 |
| **违反合法性约束** | 条件判断返回 | 22. 括号生成 |
| **重复元素导致重复解** | 同层去重 | 40. 组合总和 II、90. 子集 II、47. 全排列 II |

### 4.2 不需要剪枝的情况

| 场景 | 原因 | 代表题目 |
|-----|------|---------|
| **所有分支都合法** | 没有无效路径 | 78. 子集、46. 全排列 |
| **每层候选集独立** | 天然无重复/无效 | 17. 电话号码 |

## 🎯 五、写代码时的判断流程

```
开始递归
    │
    ▼
┌─────────────────┐
│  是否满足剪枝条件？ │  ← 先判断失败（如果失败就不需要判断成功了）
└─────────────────┘
    │是              │否
    ▼                ▼
 直接返回      ┌─────────────────┐
              │ 是否满足终止条件？ │  ← 再判断成功
              └─────────────────┘
                  │是              │否
                  ▼                ▼
            收集结果并返回    继续递归（选/不选 或 for循环）
```

### 代码模板

```cpp
void backtrack(参数) {
    // ========== 第一步：剪枝（失败出口）==========
    if (这条路已经走不通了) {
        return;  // ❌ 直接返回，不收集
    }

    // ========== 第二步：终止（成功出口）==========
    if (已经找到合法解了) {
        ans.push_back(path);  // ✅ 记录答案
        return;
    }

    // ========== 第三步：继续递归 ==========
    for (选择 : 可选集合) {
        做选择;
        backtrack(新参数);
        撤销选择;
    }
}
```

> ⚠️ **注意**：剪枝判断**必须**在终止判断之前！
> 
> 如果先判断终止，可能在一个已经非法的状态下错误地收集结果。

## 💡 六、常见误区

| 误区 | 错误理解 | 正确理解 |
|-----|---------|---------|
| "剪枝和终止是一回事" | 混为一谈 | 剪枝 = 失败返回；终止 = 成功记录 |
| "所有题都需要剪枝" | 强行加剪枝 | 有些题天然无无效分支，不需要剪枝 |
| "终止条件只能有一个" | 只写一个 if | 有些题有多个终止条件（成功 + 失败） |
| "剪枝条件写在循环外" | `if (剪枝) return` 放在循环后面 | 剪枝应该在**最前面**，越早越好 |
| "剪枝不影响正确性" | 觉得剪枝可有可无 | 没有剪枝答案也对，但会超时 |

## 📝 七、实战技巧

### 7.1 如何设计终止条件？

问自己三个问题：
1. **什么情况下当前路径是一个合法答案？** → 这就是终止条件
2. **需要记录什么？** → `ans.push_back(...)`
3. **记录完后还要不要继续？** → 通常 `return`，除非要收集所有可能

### 7.2 如何设计剪枝条件？

问自己两个问题：
1. **什么情况下当前路径已经不可能成为答案了？** → 这就是剪枝条件
2. **能不能在更早的时候发现？** → 剪枝越早，效率越高

### 7.3 快速判断口诀

> **先剪枝，后终止；**
> **剪枝是失败，终止是成功；**
> **剪枝为了快，终止为了对。**
