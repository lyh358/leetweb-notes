# LeetCode 55. 跳跃游戏 —— 贪心学习笔记

> **题目**: [55. Jump Game](https://leetcode.cn/problems/jump-game/)  
> **核心**: 给定一个非负整数数组 `nums`，你最初位于数组的**第一个下标**。数组中的每个元素代表你在该位置可以跳跃的**最大长度**。判断你是否能够到达最后一个下标。  
> **示例**:  
> ```
> nums = [2, 3, 1, 1, 4]  →  true（先跳 1 步到下标 1，再跳 3 步到最后）
> nums = [3, 2, 1, 0, 4]  →  false（无论如何都会卡在下标 3）
> ```

---

## 一、核心思想：维护最远可达距离

### 1.1 为什么不能"每次都跳最大值"？
很多人第一反应是："既然每个位置能跳的最大距离给了，那我每次选最大的跳不就行了？"  
但这样是**错误的**！因为"每次跳最大"是一个局部贪心，而本题要求的是**能否到达终点**，不是求最少步数。有时候不跳最大反而能到终点。

```
反例：nums = [3, 2, 1, 0, 4]
下标 0 能跳到 1, 2, 3
如果"每次跳最大"：0 → 3（跳 3 步）
下标 3 的值是 0，卡死了，到不了终点 ❌

但实际上：0 → 1（跳 1 步）→ ... 也到不了，这个例子确实到不了

再举一个：nums = [2, 5, 0, 0]
"每次跳最大"：0 → 2（跳 2 步），下标 2 是 0，卡死 ❌
正确路径：0 → 1（跳 1 步），下标 1 能跳 5 步，直接到终点 ✓
```

### 1.2 正确的贪心思路
不纠结"每一步怎么跳"，而是问：**我最远能到达哪里？**

维护一个变量 `range`，表示从起点出发，**目前最远能够到达的下标**。

遍历数组中的每个位置 `i`：
1. 如果当前下标 `i > range`，说明这个位置**根本走不到**，直接返回 `false`；
2. 如果能走到，就用 `i + nums[i]` 更新最远可达距离：`range = max(range, i + nums[i])`；
3. 如果 `range` 能够覆盖最后一个下标，说明可以到达。

```
nums = [2, 3, 1, 1, 4]

i=0: range=0, i<=range ✓, range=max(0, 0+2)=2  （最远能到下标 2）
i=1: range=2, i<=range ✓, range=max(2, 1+3)=4  （最远能到下标 4）
i=2: range=4, i<=range ✓, range=max(4, 2+1)=4
i=3: range=4, i<=range ✓, range=max(4, 3+1)=4
i=4: range=4, i<=range ✓, range=max(4, 4+4)=8

遍历完，返回 true ✓
```

## 二、为什么第一种代码是错的？

### ❌ 错误代码

```cpp
for(auto num : nums) {           // ⚠️ num 是数组元素的值，不是下标！
    if(range < num) return false; // ❌ 用值和下标比较，逻辑错误
    range = max(range, num + nums[num]); // ❌ nums[num] 用值当下标，可能越界！
}
```

### 错误 1：`for(auto num : nums)` 遍历的是值，不是下标

范围 for 循环 `for(auto num : nums)` 中，`num` 是 `nums[i]` 的值，不是下标 `i`。

| 下标 i | nums[i] | num（范围for） |
|:------:|:-------:|:-------------:|
| 0 | 2 | 2 |
| 1 | 3 | 3 |
| 2 | 1 | 1 |
| 3 | 0 | 0 |
| 4 | 4 | 4 |

所以 `num` 代表的是"能跳的距离"，而不是"当前在哪个位置"。

### 错误 2：`if(range < num)` 比较对象错误

`range` 是"最远能到达的下标"，应该和**下标**比较，而不是和**跳跃值**比较。

```
正确逻辑：if (range < i)  // i 是当前下标
错误代码：if (range < num) // num 是 nums[i] 的值
```

例如 `nums = [3, 2, 1, 0, 4]`：
- 第 1 轮：`num = 3`，`range = 0`，`0 < 3` 成立，直接返回 `false`！
- 但实际上下标 0 完全是可以到达的（就是起点），错误！

### 错误 3：`nums[num]` 用值当下标，严重越界

```cpp
range = max(range, num + nums[num]);
//                    ↑  num 是值，不是下标！
```

例如 `nums = [100]`：
- `num = 100`
- `nums[100]` → 数组只有 1 个元素，访问 `nums[100]` 直接**越界**！

再如 `nums = [3, 2, 1, 0, 4]`：
- 第 1 轮 `num = 3`，`nums[3] = 0`，碰巧没越界；
- 但逻辑上 `num + nums[num] = 3 + 0 = 3`，这不是"从下标 0 能跳到的最远距离"，而是"用值 3 去访问下标 3 再加起来"，完全不对。

### 总结错误原因

| 错误点 | 错误代码 | 正确代码 | 说明 |
|:------:|:-------:|:-------:|:----:|
| 遍历对象 | `auto num`（值） | `int i`（下标） | 需要知道当前在哪个位置 |
| 比较对象 | `range < num` | `range < i` | 判断当前下标是否可达 |
| 更新公式 | `num + nums[num]` | `i + nums[i]` | 当前位置 + 能跳的距离 |

## 三、正确代码实现（带完整注释）

```cpp
class Solution {
public:
    bool canJump(vector<int>& nums) {
        // ========== 贪心策略：维护最远可达距离 ==========

        // range: 从起点出发，目前最远能够到达的下标
        // 初始为 0，表示一开始只能站在下标 0
        int range = 0;

        // ========== 遍历每个位置 ==========
        // 必须用下标 i 遍历，因为我们需要知道"当前在哪个位置"
        for (int i = 0; i < nums.size(); i++) {

            // 步骤1：检查当前下标 i 是否可达
            // 如果当前下标超过了最远可达距离，说明这个位置走不到
            // 直接返回 false
            if (range < i) {
                return false;
            }

            // 步骤2：更新最远可达距离
            // 站在下标 i，最远可以跳到 i + nums[i]
            // 和之前记录的最远距离取最大值
            range = max(range, i + nums[i]);

            // 优化：如果已经能到达或超过最后一个下标，可以提前返回 true
            // if (range >= nums.size() - 1) return true;
        }

        // ========== 遍历完成 ==========
        // 如果循环正常结束，说明每个下标都是可达的（包括最后一个）
        return true;
    }
};
```

## 五、关键机制深度解析

### 5.1 为什么 `range < i` 就返回 false？

`range` 代表"最远能到达的下标"。如果当前遍历到的下标 `i` 比 `range` 还大，说明：
- 前面所有位置加起来，最远只能到 `range`；
- `range + 1` 到 `i` 之间的所有位置都**不可达**；
- 既然 `i` 不可达，后面的位置更不可能到达。

因此可以直接返回 `false`。

### 5.2 为什么不需要真的"跳"？

本题只问"能否到达"，不问"怎么跳"。所以不需要模拟每一步的跳跃路径，只需要知道"最远能到哪里"。

这是一种**覆盖问题**：每个位置 `i` 都能覆盖区间 `[i, i + nums[i]]`，问所有覆盖的并集是否能覆盖到最后一个下标。

### 5.3 与 LeetCode 45（跳跃游戏 II）的区别

| 对比项 | 本题 LeetCode 55 | LeetCode 45 |
|:------:|:----------------:|:-----------:|
| **问题** | 能否到达终点？ | 到达终点的最少跳跃次数？ |
| **返回值** | bool | int（最少步数） |
| **核心变量** | 最远可达距离 `range` | 当前步数的最远边界 `end`，下一步的最远边界 `maxPos` |
| **贪心策略** | 维护全局最远可达 | 每步在可达范围内选能跳最远的 |

## 七、易错点与面试 Tips

### ❌ 错误 1：用范围 for 遍历值而不是下标
```cpp
for (auto num : nums) {  // ❌ num 是值！
    // ...
}
// 正确
for (int i = 0; i < nums.size(); i++) {  // ✅ i 是下标
```

### ❌ 错误 2：比较对象错误
```cpp
if (range < num)  // ❌ num 是值，不是下标
if (range < i)    // ✅ i 才是下标
```

### ❌ 错误 3：更新公式用值当下标
```cpp
range = max(range, num + nums[num]);  // ❌ 严重错误，可能越界
range = max(range, i + nums[i]);      // ✅ 当前下标 + 能跳的距离
```

### ❌ 错误 4：忘记检查 `range < i`
```cpp
// 如果不检查，可能会误以为不可达的位置也能到达
```

### ✅ 面试回答框架
1. **思路**：维护一个"最远可达距离"`range`，遍历每个位置；
2. **检查**：如果当前下标 `i > range`，说明不可达，返回 false；
3. **更新**：`range = max(range, i + nums[i])`；
4. **复杂度**：时间 $O(n)$，空间 $O(1)$；
5. **关键**：必须用下标遍历，不能用范围 for 遍历值。

## 八、一句话总结

> **不要模拟"怎么跳"，只要关心"最远能跳到哪儿"。一路走一路更新最远边界，如果当前位置连边界都够不着，那就彻底没戏了。**

| 要点 | 内容 |
|------|------|
| 核心变量 | `range`：目前最远能到达的下标 |
| 遍历方式 | 必须用下标 `i` 遍历，不能用范围 for |
| 不可达判断 | `if (range < i) return false` |
| 更新公式 | `range = max(range, i + nums[i])` |
| 时间复杂度 | $O(n)$ |
| 空间复杂度 | $O(1)$ |
| 最大坑点 | 混淆"值"和"下标"，用 `nums[num]` 越界 |
