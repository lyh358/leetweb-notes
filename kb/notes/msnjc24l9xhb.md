# 昇腾锂电池寿命预测：项目全景与技术深挖

## 1. 项目定位

面向 BMS 的电池健康管理与安全预警，把 NASA 电池循环数据上的 GRA + PCA + LSTM 容量/RUL 预测算法，从 PC 训练环境迁移到 Atlas 200I DK A2（ARM64 Linux、Ascend 310B4）边缘平台。

系统不是单一模型，而是两条链路：

1. 算法链：原始循环数据 → 退化特征 → GRA 筛选 → PCA 压缩 → LSTM 预测容量 → EOL/RUL 推断。
2. 工程链：PyTorch `.pth` → ONNX → ATC 编译 → OM → ACL Lite 板端推理 → 指标与结果落盘。

当前证据等级：算法和部署流程为 `[文档陈述]`，工作区没有训练、推理源码和运行产物；量化指标属于 `[待补证]`。

## 2. 应先区分的三个概念

- SOH：当前可用容量与额定/初始容量之比，反映健康程度。
- EOL：容量下降到失效阈值的时刻，常用初始容量的 80%，但必须以真实实验定义为准。
- RUL：从当前循环到 EOL 还剩多少循环。项目模型直接预测的是容量序列，再由预测曲线首次越过阈值的位置换算 EOL/RUL；不要把容量回归和 RUL 分类混为一谈。

## 3. 总体架构和端到端数据流

```text
NASA 充放电循环数据
        │
        ├─ 数据清洗、按循环对齐、训练测试划分
        │
        ├─ 提取 11 维充/放电退化特征
        │
        ├─ GRA：按与容量退化的关联度筛选强相关特征
        │
        ├─ PCA：消除相关性并压缩为 4 维健康因子
        │
        ├─ 标准化 + 长度 21 的滑动窗口
        │
        └─ LSTM(4→hidden=100) + FC(100→1) → 容量预测
                                         │
PC: .pth → ONNX(opset 12, fixed shape)   │
                    │                     │
Ascend: ATC → OM → ACL Lite → 反归一化 → RMSE/MAE/R²/EOL
```

## 4. 算法侧技术细节

### 4.1 为什么采用数据驱动

电化学模型可解释性强，但需要准确参数和工况建模；复杂温度、倍率和老化机理下辨识成本高。数据驱动方法可以直接从历史循环学习非线性退化规律，工程部署更直接。代价是依赖数据覆盖、外推能力弱、可解释性较低。

更成熟的回答是：不是说数据驱动绝对优于模型驱动，而是当前任务有成组历史循环数据，目标是预测性能和可部署性，因此选择数据驱动；生产系统可进一步做物理约束或混合建模。

### 4.2 11 维特征应如何理解

现有文档只确认“来自充电和放电阶段的 11 个退化特征”，未列出完整字段。面试前需要从论文补齐每个特征的定义、单位和提取区间。常见候选包括恒流/恒压阶段时长、电压区间通过时间、温度统计量、放电容量等，但在没有论文原文前不能把这些候选说成项目事实。

### 4.3 GRA 的目的和实现

GRA（灰色关联分析）衡量各特征序列与参考容量退化序列在变化趋势上的接近程度，适合样本较少、关系不完全已知的场景。

典型过程：

1. 无量纲化参考序列和比较序列；
2. 计算绝对差 `Δ_i(k)=|x_0(k)-x_i(k)|`；
3. 计算关联系数：

```text
ξ_i(k) = (Δ_min + ρΔ_max) / (Δ_i(k) + ρΔ_max)
```

4. 对所有时间点求均值得到关联度；
5. 以文档中的 0.75 为阈值，从 11 维保留 9 维。

目的：先去掉对退化不敏感的特征，降低噪声。限制：阈值具有经验性；GRA 更偏趋势相似，不等于因果关系，也不自动解决特征之间的共线性。

### 4.4 为什么 GRA 后还要 PCA

两者解决不同问题：

- GRA 是有监督式的相关性筛选，问“哪个原始特征与目标有关”；
- PCA 不使用标签，问“如何把保留特征投影到少数正交方向并保留主要方差”。

GRA 去弱相关，PCA 去冗余和共线性，最终得到 4 维输入。PCA 的实现应包括标准化、协方差矩阵、特征值分解、按累计解释方差选择主成分。必须仅在训练集上拟合 GRA/PCA/标准化参数，再应用到测试集，否则会发生数据泄漏。

### 4.5 LSTM 网络和张量形状

根据现有模型示例：

- 输入 `x`：`[batch=1, seq_len=21, feature=4]`；
- `h0/c0`：`[num_layers=1, batch=1, hidden=100]`；
- LSTM 输出 `out`：`[1,21,100]`；
- 取 `out[:,-1,:]`：`[1,100]`；
- 全连接层输出容量预测 `y`：`[1,1]`；
- 同时输出 `hn/cn`：`[1,1,100]`。

LSTM 每个时间步的核心为：

```text
f_t = sigmoid(W_f[x_t,h_{t-1}] + b_f)       遗忘门
i_t = sigmoid(W_i[x_t,h_{t-1}] + b_i)       输入门
g_t = tanh(W_g[x_t,h_{t-1}] + b_g)          候选记忆
c_t = f_t*c_{t-1} + i_t*g_t                 更新长期状态
o_t = sigmoid(W_o[x_t,h_{t-1}] + b_o)       输出门
h_t = o_t*tanh(c_t)
```

相较普通 RNN，`c_t` 的近线性记忆通道和门控缓解长序列反向传播中的梯度消失。它不能保证不发生梯度问题，训练时仍可能需要标准化、合理初始化和梯度裁剪。

### 4.6 为什么窗口长度为 21

当前只能确认训练和部署都使用 21，无法从材料确认它如何通过实验选择。正确口径：21 是模型训练时确定的超参数，部署必须保持一致；它平衡局部退化趋势信息与计算/样本数量。要回答“为什么恰好 21”，必须补充窗口消融实验。

### 4.7 指标如何计算

```text
MAE  = mean(|y_i - ŷ_i|)
RMSE = sqrt(mean((y_i - ŷ_i)^2))
R²   = 1 - Σ(y_i-ŷ_i)² / Σ(y_i-mean(y))²
```

EOL 误差应定义为 `|预测首次越过阈值的循环 - 真实首次越过阈值的循环|`。回归任务中的“准确率”没有统一定义，可能是 `1-MAPE`、命中误差带比例或其他自定义指标；未给公式前不要直接使用“99.8% 准确率”。

## 5. 模型转换与昇腾部署

### 5.1 `.pth → ONNX`

关键步骤：重建一致的 `nn.Module`、加载 `state_dict`、调用 `eval()`、构造三输入 dummy tensor、以 opset 12 导出、不开启 `dynamic_axes`。

`eval()` 的作用是固定 Dropout/BatchNorm 等推理行为；当前 LSTM 示例本身没有 Dropout/BN，但使用 `eval()` 仍是正确的通用部署流程。导出后还应使用 ONNX checker，并用 ONNX Runtime 与 PyTorch 对同一输入做数值比对；现有资料没有这部分结果。

### 5.2 为什么要固定 Shape

固定 `x:1,21,4; h0:1,1,100; c0:1,1,100` 后，编译器可以提前完成算子选择、内存规划和部分图优化。代价是 batch、窗口长度和特征数不能运行时自由变化；若产品要支持多个窗口，可准备多个 OM 或采用平台支持的动态档位方案。

### 5.3 ATC 命令

```bash
atc --model=./models/LSTM_net_raw_B0005_with_hc.onnx \
    --framework=5 \
    --output=./models/LSTM_net_raw_B0005_with_hc \
    --input_format=ND \
    --input_shape="x:1,21,4;h0:1,1,100;c0:1,1,100" \
    --log=info \
    --soc_version=Ascend310B4 \
    --precision_mode=force_fp32
```

各参数目的：指定 ONNX、目标输出、普通 ND 张量格式、静态输入形状、目标 SoC 和精度策略。输入名必须与 ONNX graph 完全一致。

### 5.4 为什么使用 FP32

材料给出的理由是连续值回归对误差敏感，因此优先 FP32。更严谨的做法应是用同一测试集比较 FP32/FP16 的端到端时延、RMSE 和 EOL 误差，再决定是否值得降精度。没有实测对照时，只能说“选择保守精度策略”，不能断言 FP16 必然不满足要求。

### 5.5 OM 和 ACL Lite 推理生命周期

板端运行流程：

1. 初始化 ACL、设备、context、stream；
2. 加载 OM，读取输入输出描述；
3. 对原始数据应用与训练一致的 GRA/PCA/标准化参数；
4. 构造连续内存的 FP32 输入张量；
5. Host→Device 拷贝并执行模型；
6. Device→Host 拷贝输出；
7. 反归一化、计算指标、保存 CSV/JSON/图片；
8. 释放 dataset、buffer、model、stream、context、device 和 ACL runtime。

ACL Lite 是对 ACL 生命周期、内存拷贝和模型执行的 Python 封装，降低样板代码；底层仍是 ACL runtime。

### 5.6 LSTM 状态在静态图中的适配

把 `h0/c0` 变成显式输入、`hn/cn` 变成显式输出，使状态跨一次 OM 调用成为可能。但是否真的跨滑窗传递必须由真实推理脚本确认。

需要理解两种策略：

- 独立窗口：每个 `[t-20,t]` 从零状态推理，依靠窗口内 21 步建模；语义清晰。
- 有状态窗口：把上一窗口 `hn/cn` 送入下一窗口；能延续更长状态，但相邻窗口有 20 步重叠，会重复输入，需要专门训练或改为不重叠 chunk 才更严谨。

## 6. 常见故障定位

| 现象 | 优先检查 | 原因 |
| --- | --- | --- |
| `load_state_dict` 失败 | 层数、hidden size、输入维、key 前缀 | 网络结构与权重不一致 |
| ONNX 数值不一致 | `eval()`、预处理、opset、输出节点 | 导出语义或数据处理差异 |
| ATC 找不到输入 | ONNX graph 的真实输入名 | `--input_shape` 名称不一致 |
| ATC 算子不支持 | LSTM 表达、opset、CANN 版本 | 编译器不支持该算子组合 |
| OM 输入报错 | dtype、shape、字节数、连续内存 | 静态模型接口严格匹配 |
| 板端预测整体偏移 | 标准化/PCA参数、特征顺序、反归一化 | 训练与部署预处理不一致 |
| 前几次预测异常 | hidden state 初始化、窗口暖启动 | 时序上下文不足 |

## 7. 技术选型权衡

- LSTM vs GRU：LSTM 表达能力强但参数和状态更多；GRU 更轻量，可作为端侧替代对照。
- LSTM vs 1D CNN/TCN：CNN/TCN 更容易并行和静态部署，但需验证长程退化建模能力。
- 边缘 vs 云：边缘低时延、弱网可用、隐私好；云端算力和集中维护更强。实际系统可采用边缘实时推理、云端周期训练。
- ONNX/OM 静态化：换来编译优化与确定性，牺牲动态输入灵活性。
- FP32 vs FP16：精度稳定性与时延/带宽的权衡，必须用数据决策。

## 8. 生产化还缺什么

- 在线 BMS 数据接入、输入合法性与传感器故障处理；
- 跨温度、倍率、不同电芯体系的域外泛化；
- 模型版本、特征版本和归一化参数的一致性管理；
- 运行时监控、超时与 CPU 回退；
- 模型签名、灰度升级和回滚；
- 对电池安全相关系统的置信度估计与失效保护；
- 可复现的性能、功耗、精度基准。
