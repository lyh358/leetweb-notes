这道题（力扣 287）的快慢指针是Floyd 判圈算法，把数组当成链表来看。下面一步步拆解。
# 一、数组怎么变成"链表"？
数组 nums 的值域是 [1, n]，索引是 [0, n]。把索引当节点，值当下一个节点的地址：
```plain
索引:  0   1   2   3   4
nums: [1,  3,  4,  2,  2]
```
看成链表就是：
`0 → 1 → 3 → 2 → 4 → 2 → 4 → 2 → ...`
从索引 0 出发，nums[0] = 1，走到索引 1
nums[1] = 3，走到索引 3
nums[3] = 2，走到索引 2
nums[2] = 4，走到索引 4
nums[4] = 2，又走到索引 2
2 → 4 → 2 形成了一个环！
二、为什么一定有环？
数组有 n+1 个数，值都在 [1, n] 之间。根据鸽巢原理，至少有一个数出现两次。
这个重复的值就是有两个不同的索引指向同一个节点，链表必然成环。
三、快慢指针第一阶段：找相遇点
把数组当链表，从 nums[0] 开始走：
slow 每次走一步：slow = nums[slow]
fast 每次走两步：fast = nums[nums[fast]]
就像操场跑步，快的人总会追上慢的人（进入环后），所以它们一定会在环内某处相遇。
```plain
0 → 1 → 3 → 2 → 4 → 2 → 4 → 2 ...
          ↑____________↑
              环
```
slow: 0→1→3→2→4→2→4...
fast: 0→3→4→4→2→4→2...
最终在某点相遇（比如 4）
四、第二阶段：为什么从起点和相遇点同步走，相遇处就是环入口？
这是 Floyd 算法的数学结论：
设：
起点到环入口的距离 = a
环入口到相遇点的距离 = b
相遇点回到环入口的距离 = c（即环长 = b + c）
快慢指针相遇时：
slow 走了 a + b
fast 走了 a + b + n(b + c)（多绕了 n 圈）
因为 fast 速度是 slow 的 2 倍：
plain
2(a + b) = a + b + n(b + c)
=> a + b = n(b + c)
=> a = n(b + c) - b = (n-1)(b+c) + c
这意味着：从起点走 a 步 = 从相遇点走 c 步（加若干整圈）。
所以：
一个指针从起点（0）出发
一个指针从相遇点出发
都以每次一步的速度走
它们会在环入口相遇！

```
// 第一阶段：找相遇点
int slow = nums[0];           // slow 先走一步到 nums[0]
int fast = nums[nums[0]];     // fast 先走两步

while (slow != fast) {
    slow = nums[slow];        // 慢：一步
    fast = nums[nums[fast]];  // 快：两步
}

// 第二阶段：找入口
int ptr = 0;                  // ptr 从起点（索引0）出发
while (ptr != slow) {
    ptr = nums[ptr];          // 各走一步
    slow = nums[slow];
}
return ptr;                   // 相遇点就是重复数
```
